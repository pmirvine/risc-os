This chapter adds the Notepad - pages of notes you type straight onto, with a contents page to find them by - and two things that tie the organiser together. The Link tool joins any two entries (a lunch in the Diary and the person you're having it with, say), so that one leads to the other; and a Back button takes you back to where you were before you followed a link or turned to another section. The result is !Org14.

Pages of notes

A page of the notepad is a title, its text, and its place in the notepad:

{ id: 2, title: 'Holiday ideas', order: 1,
  text: 'Cornwall: St Ives in June?\nThe Lake District ...' }
The text is a string with \n between its lines. The pages are kept in a collection like every other section's, with two additions:

list gives the pages in order. moveTo moves a page to another place: it takes the page out of the list, puts it back at position i, and then renumbers every page whose order has changed.

splice

Putting the page back uses an array method you haven't needed before. splice(i, n, ...items) changes an array in place: at position i it takes out n items and puts in whatever follows. With n 0 it only puts things in:

const a = ['A', 'B'];
a.splice(0, 0, 'C');       // a is now ['C', 'A', 'B']
a.splice(1, 1);            // takes out 'A': ['C', 'B']
Only the pages whose number really changes are updated, so moving a page near the end of a long notepad doesn't mark every page as changed. Check tests it:

Typing on the page

Writing a multi-line text editor is a job in itself (chapter 17 shows how to make a small one), so the notepad uses the one the desktop provides. A TextArea (appendix C) is a box of editable text placed on a window: it draws itself on a canvas of its own in the window's work area, wraps words, scrolls, and takes clicks inside it and keys while it has the caret. You give it a position and a size, and listen for its 'change' event:

rect is the space on the right-hand page below the heading - a getter, because the page's position comes from the binder (this.org.pages). show makes the TextArea with the page's text, and every change puts the new text straight into the collection, which marks the document as changed (the * in the title) as any other change does. hide takes the TextArea away. open turns to a page: it hides the old one, shows the new one and gives it the caret, so you can type at once.

The window calls a section's show and hide (chapter 10) when you open it and when you go to another tab, so the TextArea is only there while the Notepad is.

Who gets the keys first

The notepad page lives in the organiser's window, and that window already has click and key handlers of its own: a click chooses an entry, and keys do things - Delete deletes the chosen entry, Page Up turns the page, Insert adds an entry:

Now imagine typing a note and pressing Backspace. The key goes to the window, and if the window's handler saw it first, it would delete the chosen entry instead of a letter. The TextArea must see the key first, and only let it go on to the window if it doesn't want it.

It does, because of how it adds its handlers. In chapter 1 the Emitter called handlers in the order they were added. The desktop's windows use the same idea, with one extra: a handler added with { first: true } goes in front of the others. The TextArea adds its handlers like that:

win.on('click', (ev) => this.click(ev), { first: true });
win.on('key', (ev) => this.key(ev), { first: true });
Handlers stop as soon as one returns true. The TextArea returns true for a click inside itself and for a key it uses while it has the caret, so the window never sees those; everything else - a click on a title, a key like F3 while the note has the caret - goes on to the window as usual. That's why the Notepad's own click and key are so short:

The opposite matters as much. When the page is put away, the TextArea's handlers must go too, or a TextArea no longer on the screen would go on taking the window's clicks and keys. So remove - called by the Notepad's hide - takes its handlers away before its canvas. The desktop's on returns a function that removes the handler again (like the Emitter's off), and the TextArea keeps those functions and calls them all (shortened a little here):

remove() {
  for (const off of this._offs) off();
  this.canvas.remove();
}
Anything that adds handlers to someone else's window should be as tidy.

Ctrl-D: today's date

The Style Guide gives Ctrl-D the job of typing the date. The TextArea doesn't know that key, so it goes on to the window, which asks the section first (this.section.key(ev) above). The Notepad's key checks that its TextArea has the caret and the key is code 4 - Ctrl with a letter gives the letter's place in the alphabet, and D is the fourth - and puts the date in at the caret with insert. D.format is chapter 11's, which uses the desktop's formatTime codes: %ZDY %MO %CE%YR is the day without a leading zero, the month's name and the year, as in 25 September 2026.

Linking entries

Some entries belong together: a lunch in the Diary and the person it's with, a to-do and the notepad page with its details. A link joins two of them. It is kept as the two entries' refs - the { section, id } objects chapter 12 introduced - in a collection of its own:

sameRef says whether two refs are the same entry. A link has no direction, so of looks at both ends: for each link, if one end is the entry, the other end is linked to it. flatMap (chapter 9) makes that easy - each link gives an array of one ref, or of none, and flatMap joins them into one array.

link won't join an entry to itself, or join two entries twice (either way round); forget removes the links of an entry that's been deleted, so no link is left pointing at nothing. Deleting calls it, in Tools.remove:

Going back

Following a link can take you anywhere in the organiser, so the toolbox gets a Back button. The window keeps a history: each time you go somewhere else, it remembers where you were.

Where you are is two things: which section is open (this.current) and where that section is - the Diary's view and day, the Notepad's page. Each section says where it is with state and goes back there with restore. The Section class gives every section a plain version, which just remembers the view:

and sections with more to remember give their own. The Diary adds its day:

The Notepad remembers its page, and its restore hides the TextArea before changing page and shows it again after, so the text on the screen is the page's:

remember pushes { i, s } onto the history - shift takes the oldest off the front once there are 30, so it can't grow for ever - and back pops the latest one off, opens that section and restores its state. With nothing to go back to, it beeps.

A default value

open(i, remember = true) gives its second parameter a default value: called as open(2), remember is true. It's the same idea as the defaults in destructured parameters in chapter 2. back calls open(h.i, false), because going back mustn't itself be remembered, or Back would go to and fro between the same two places.

go also calls open(i, false), after calling remember itself. That isn't the same: open does nothing at all if the section is already open, so a link from one diary entry to another wouldn't have been remembered. Calling remember first means every go can be undone with Back. The Diary does the same when a click in the month or year view turns to a week (this.org.remember() in its click).

Trying it

1 Run !Org14 and open the sample Diary. In the Diary, Lunch with Bob on Saturday 26 September has a chain: it's linked to Bob's card.

2 Click the chain and choose Address: Jones, Bob from the menu. The Address section opens at the letter J with Bob chosen. Click the Back button: you're back at the week.

3 Click the Notepad tab and click Holiday ideas. Type a line, and press Ctrl-D to add today's date. Press Backspace: it deletes a letter, not the page.

4 Drag Gift ideas to the top of the contents: it becomes page 1.

5 Click Gift ideas, click the Link button, then click the To do tab and click Buy a birthday card for Bob. Both now have chains.

Summary

  • The desktop's TextArea gives a window several lines of editable text; show it while its page is shown and remove it when it isn't.

  • A handler added with { first: true } runs before the others, and returning true stops the rest: that's how a TextArea takes its keys before the window does.

  • Whatever adds handlers to a window must take them away again when it's finished.

  • Ctrl with a letter gives the letter's place in the alphabet: Ctrl-D is 4.

  • splice(i, n, ...items) takes items out of an array and puts others in, in place.

  • A link is two refs; sameRef compares them, and a deleted entry's links are forgotten.

  • A history of { section, state } makes a Back button; each section says where it is with state and goes back with restore.

  • A parameter can have a default value: open(i, remember = true).
