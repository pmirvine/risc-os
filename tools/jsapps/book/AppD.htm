Acorn's RISC OS 3 Style Guide (1993) describes how a RISC OS application should look and behave, so that everything a user learns in one program works in the next. This appendix is a checklist of its rules for the kind of application this book builds, with the chapter where !Contacts or !Organiser does each thing. Go through it for your own applications.

The icon bar

  • One icon on the icon bar. Select on it opens a new document (or the main window) (7).

  • Menu on it gives at least Info and Quit, and Choices... if there are choices (7, 9).

  • Files dragged onto it are loaded (8).

  • Its interactive help says what clicking does (9).

Documents and files

  • Documents have a file type of their own, with a name and an icon, set up in !Boot (7).

  • Double-clicking a document loads it; if the program is already running, that copy loads it (7).

  • A document that is already open is brought to the front, not loaded twice (7).

  • The document's full name is in its window's title, followed by * as soon as it has unsaved changes; the * goes when it is saved (7).

  • Other programs' formats (CSV, vCard, iCalendar) are loaded when dropped on you, not claimed as your own file types, and exported with Save boxes of their own (8, 16).

  • The file format is written down, and carries a version number (7; appendix E).

  • Info about the document shows its name, whether it's changed and how much it holds (9).

Saving

  • F3 opens the Save box; the file icon can be dragged to a directory display or into another program (7, 8).

  • A name with a full path can be typed instead, and OK (or Return) saves (7).

  • Saving clears the "modified" mark and updates the title (7).

Closing and quitting

  • Closing a changed document asks: Discard, Cancel or Save (7).

  • Quitting, or the desktop shutting down (PreQuit), asks about unsaved changes before anything is lost (9).

  • Nothing is kept in memory after its window closes without the user knowing (7).

Menus

  • The window's menu is built each time it opens, from the current state: items that can't be used are shaded, options that are on are ticked (4).

  • Item names start with a capital and go on in small letters: Select all, not Select All (3).

  • An item that opens a dialogue box that stays until closed ends with ... (9).

  • Shortcut keys are shown at the right of their items (4).

  • Menu over an unselected item selects it just for the menu (2).

Dialogue boxes

  • The default action is the button at the bottom right, with the thicker border; Return does it, Escape cancels, and Cancel is to its left (3).

  • Buttons are named with verbs: Save, Delete, not Yes and No (3, 4).

  • Tab, Shift-Tab and the arrow keys move between fields; Return moves to the next field until the last (3).

  • Nothing changes until the action button is pressed; the dialogue box edits a copy (3).

  • A problem is reported, and the caret put in the field that needs changing (3).

  • A question that could lose work (Delete) asks first, if the user wants it to (4, 9).

Selection

  • Select chooses one item; Adjust adds or removes one; double-click opens (2).

  • Ctrl-A selects everything; Ctrl-Z clears the selection (4).

  • What is selected is shown in reverse (2).

Toolbars and toolboxes

  • Choices made again and again go in a toolbar or toolbox: a pane attached to the document's window, like Draw's (5, 11).

  • Its buttons are 3D, repeat things in the menus, and are shaded when they can't be used (5).

  • Every button has interactive help (9).

The keyboard

  • A window gets the input focus when it's clicked in or opened; keys it doesn't use are passed on, so F12 and the other desktop keys always work (2).

  • The standard keys (4, 6, 9): 
    F1  help               F3  save             F4  find
F5  go to              F6  sort             F8  undo
F9  redo               ^F2 close window     Print print
Insert  insert         Delete  delete       ^A  select all
^Z  clear selection    ^D  insert the date (a notepad)
  • Alt is never used for shortcuts.

Colour

  • Colour is used only inside the data area: window frames, menus and dialogue boxes keep the desktop's own colours (10).

  • Colour is never the only difference: overdue to-dos have a symbol as well, planner categories a pattern as well as a colour (13, 15).

  • Not too many colours, and the user can change them (16).

Choices

  • Choices... on the icon bar menu opens a box with Default, Cancel, Set (use them now) and Save (use them and keep them) (9).

  • Choices are saved in Choices:, not in the application's directory (9).

Help

  • Every window, icon, menu item and the icon bar icon has interactive help (9).

  • The application directory has a !Help file (9).

Errors

  • Messages are plain and say what to do: no numbers, no "fatal", at most one short apology (2, 8).

  • Error boxes are centred on the screen; boxes opened from a menu, near the pointer.
