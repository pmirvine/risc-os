This appendix lists the parts of the desktop's programming interface that this book uses on top of those in appendix B of the first book; a few that the first book's appendix already lists are repeated here because this book uses more of them (they're marked also in the first book). The names are among those a module imports from 'riscos', or reached through wimp, vfs and os. The chapter where each is first used is given in brackets.

Applications and their files

A file type of your own (7)

An application that saves documents gives them a file type: a number from &000 to &FFF that no other program uses (!Contacts uses &1C4, !Organiser &1C5). Its !Boot file, which the Filer runs when it first shows the application, names the type and says what double-clicking one does:

Set Contacts$Dir <Obey$Dir>
IconSprites <Obey$Dir>.!Sprites
Set File$Type_1C4 Contacts
Set Alias$@RunType_1C4 Run <Contacts$Dir>.!Run %%*0
In an Obey file, %0, %*0 and so on are replaced by the file's own parameters, so %% is written for a % that has to stay: the run action then passes the double-clicked file's name on to !Run. The !Sprites file holds the file icons, file_1c4 and small_1c4, as well as the application's.

The file it was started with (7)

A file passed to a program when it starts is in ctx.argv[0]. (ctx.file is the program itself, and ctx.dir the directory it's in.)

const file = ctx.argv[0];
if (file) await app.open(file);

Messages (7, 9; also in the first book)

task.onMessage('DataOpen', (msg) => ...)
A file of some type was double-clicked while the program is running: msg.path, msg.filetype. Return true to take it; the running copy then loads it rather than a second copy starting.

task.onMessage('PreQuit', (msg) => ...)
The desktop is shutting down. With unsaved changes, call msg.object() to stop it, ask, and if the user discards them quit, and start the shutdown again unless only this program was being quit (msg.single): 
if (!msg.single) wimp.emit('hotkey:CtrlShiftF12', {});
task.onMessage('Quit', () => task.quit())
Quit now.

wimp.sendMessage('DataOpen', { path, filetype }, { to: t }) (7)
Send a message to another task (here the running copy of the program, found in wimp.tasks), as !Contacts does when a second copy starts.

vfs.canonical(path) (7)
The full, proper form of a file name (<Obey$Dir> and the like worked out, the right case), so two names for the same file compare equal.

Windows, panes and sprites

Panes (5)

A pane is a window that the Wimp keeps in front of another and moves with it, such as a toolbar. Make it with flags: { pane: true } and attach it:

w.attachPane(pane, { dx: 0, dy: 0, h: 44, fitWidth: true });
w.attachPane(box, { dx: 0, dy: 0, w: 64, fitHeight: true });
dx, dy place it relative to the window's work area on screen; fitWidth / fitHeight make it as wide or as tall as the window. It opens, closes and goes away with the window.

A sprite area of your own (5)

const area = sprites.spritesFromFile(
  await vfs.readFile(ctx.dir + '.Sprites'));
task.createWindow({ ..., spriteArea: area });
Icons in a window with a spriteArea find their sprites there first. Keeping a program's pictures out of the Wimp's pool (where IconSprites puts them) means they can't clash with another program's sprites of the same names.

Icons and fields

Icon descriptions (3)

{ x, y, w, h, text: 'Save', border: true, filled: true,
  hcentre: true, vcentre: true, button: 'click',
  validation: 'R6,3', name: 'save', help: 'Click SELECT to save.' }
button
'click' (reports clicks), 'writable' (a field you type into), 'radio' (selected by a click: an option icon with sprite: 'optoff', validation: 'Soptoff,opton'), 0 (nothing: a label or display field).

validation
R5,3 an action button; R6,3 the default button (a thicker border); A0-9 the characters that may be typed; S the sprites.

name, help
Find it with w.iconByName('save'); help is its interactive help.

Changing one
icon.setText(t), icon.setSprite(s), icon.setState({ shaded, selected, deleted }); icon.text, icon.selected, icon.shaded.

Where things are in a window (1, 2, 3)

w.work
The window's work area on the page, for things that draw themselves into it (a TextArea's canvas, or chapter 17's text box).

w.scrollX, w.scrollY, w.scrollTo(x, y) (2)
How far the work area is scrolled, and scrolling it (a list keeping its current row in view).

w.workToScreen(x, y) (3)
A work-area point as a position on the screen (to open a menu or a box next to something).

Moving between fields (3)

In a window made with returnNext: true, Return in a writable field moves to the next one; the last field's Return is reported as a key, so it can press the default button. Tab, Shift-Tab, Up and Down move through the writable fields and text areas in reading order (top to bottom, left to right). When the caret moves from one icon to another the window gets a 'caretmove' event, { from, to } (used by chapter 17's text box). wimp.setCaret(w, icon) puts the caret in a field.

Handlers that go first (14)

const off = w.on('click', (ev) => ..., { first: true });
off();                       // take the handler away again
{ first: true } puts a handler before the ones already there, so a gadget inside a window (a text area) sees clicks and keys before the program's own handlers. on returns a function that removes the handler: a gadget that is taken away must remove its handlers too (chapters 14 and 17).

TextArea (3)

Several lines of editable text in a window, for addresses and notes:

const notes = new TextArea(w, { x: 8, y: 40, w: 300, h: 120,
  text: 'Hello' });
notes.text                   // the text; setting it redraws
notes.on('change', () => ...)    // after every edit
notes.focus()                // give it the caret
notes.readOnly = true        // (not used in this book)
It draws itself, takes clicks inside it and keys while it has the caret (before the window's own handlers), wraps words and scrolls. Chapter 17 builds a text area of your own.

Dialogue boxes and messages

reportError(message, { category, cancel, title }) (2; also in the first book)
An error box, or with category: 'info' an information box. With cancel: true it has OK and Cancel; it resolves 1 for OK and 2 for Cancel.

query({ task, title, message, buttons }) (4; also in the first book)
A box with your buttons (['Delete', 'Cancel']); resolves the button's text, or null if it was closed. The first button is Return's, the last Escape's.

discardChanges(task, message) (9)
The Discard/Cancel question; resolves true to discard.

infoBox(task, { name, purpose, author, version }) (9; also in the first book)
An Info box, for an Info submenu.

Choices (9)

const prefs = await choices.read('Contacts', { sort: 'last' });
choices.write('Contacts', prefs);
Choices are kept as JSON in Choices:Contacts (written to <Choices$Write>), not beside the program, as the Style Guide asks: a program may be on a disc that can't be written to. read gives the saved choices over the defaults, or a copy of the defaults if there are none.

Drag and drop

'dataload' (8; also in the first book)
Files dropped on a window: ev.files, each { path, filetype, name }. On the icon bar icon: its onDataLoad(ev).

'datasave' (8)
Another program's Save box dropped on a window: ev.leafname, ev.filetype, and await ev.receive() gives the data. (An icon bar icon can have an onDataSave(ev) too; the book's programs don't use it.)

dragSave(ev, { task, leafname, filetype, getData, sprite }) (8)
Call from a 'drag' event to drag a file icon out of a window. Dropped on a directory display the file is written there; dropped on another program's window the data goes to it. Resolves the file's full name, '' if the data went straight into a program, or null.

wimp.drag({ event, box, sprite, type }) (12)
Drag a box or sprite with the pointer (event is the drag event's pointerEvent, box on the screen); resolves where it was dropped: { window, icon, x, y, sx, sy, shift } (x, y in that window's work area). The organiser drags entries to other days and into the wastebasket this way.

Dates and text (11)

formatTime('%W3 %ZDY%ST %MO %CE%YR', date)
                           // 'Fri 25th September 2026'
The desktop also gives DAYS (DAYS[0] is 'Sunday'), MONTHS, ordinal(22) ('nd') and textWidth('Hello', '12px Homerton') (a width in pixels); the book's programs don't use them.

Some of formatTime's codes, as RISC OS's Territory module has them:

%24 %12 hours (0-23, 1-12)    %MI minutes   %SE seconds
%AM am or pm                  %WE Friday    %W3 Fri
%DY 25 (%ZDY without a 0)     %ST th        %MO September
%M3 Sep   %MN 09              %CE%YR 2026   %YR 26

Printing (16)

if (!os.printers) reportError('Load !Printers first');
else os.printers.print({ title: 'Week', canvas });
os.printers is there only while !Printers is running. print takes { title, text }, { title, html, css }, { title, canvas } or { title, images }. Call it from a click or menu choice.

Interactive help (3, 9)

While !Help is running it shows the help for whatever the pointer is over:

An icon
its help (given in its description, or set later: icon.help = '...').

A menu item
help in its description (text, or a function giving text).

A window
help in its description, or a 'helprequest' handler that sets ev.text (for help that depends on where the pointer is).

The icon bar icon
help given to task.addIconbarIcon.

|M in help text starts a new line.

Templates from the disc (not used in this book)

The book builds its windows in code, but a program can also use a Templates file made with a template editor on another RISC OS computer:

const w = await task.createWindowFromTemplate(
  ctx.dir + '.Templates', 'main');
const t = await loadTemplates(ctx.dir + '.Templates');
Icons keep their template numbers: w.icons[3].
