The diary can show the time four ways, but so far there is nothing in it you didn't put there with a text editor. This chapter makes it a real diary. You'll add appointments with a dialogue box, change them, make them repeat every week or every month, choose them, drag them to another day and throw them into the wastebasket. The Anniversary section gets its pages too, and each birthday also appears in the diary on its day, so it needn't be written twice. The program is !Org12.

It's the biggest step of Part Two, because choosing, deleting and dragging are written once, for every section: the To do list, the notepad and the planner will get them for nothing in the chapters that follow.

Appointments

An appointment is a plain object, like a contact. The comment at the start of the diary's part of Store says what's in one:

date is a key, as in chapter 11, and time and end are kept the same way: '09:30', always with two digits for the hour, so that times sort as text too. An appointment with no time (a day out, say) has an empty one. alarm is how many minutes before the appointment to be reminded; nothing looks at it yet (that's chapter 16). repeat is null for an appointment that happens once. STEP comes into it later in the chapter.

The Appointment box

Appointments are made and changed in a dialogue box built with chapter 3's Form. The boxes for all the organiser's entries live in one module, Entries, which knows nothing about windows or binders: each function takes an entry, shows the box, and resolves to the new fields, or null if you chose Cancel.

The diary keeps '2026-09-25', but people type 25/09/2026, so showDay turns a key into what the box shows, and D.parseDay (chapter 11) turns what was typed back into a key.

Chapter 3's address book made its one box when it was first needed, with form ??= makeForm(task). The organiser will have several boxes, so form keeps them in a Map by name and makes each the first time it is asked for. After that the same box is used again, already built.

The Alarm and Repeat fields are pop-up menus, and each choice on them stands for a value in the entry: "15 minutes" is 15, "Every week" is 'week'. ALARMS and REPEATS are lists of [name, value] pairs, and two little functions look things up in them either way round. valueOf finds the pair whose first item is the name chosen, and gives its second. In nameOf, the function's argument is [, x]: a pair, with its first item skipped (the comma with nothing before it, as in chapter 8's [last, first, , title]), and its second called x. ?.[0] then takes the name from the pair found - or gives undefined, rather than an error, if there wasn't one. (?. works before square brackets just as it does before a property name.)

The fields are chapter 3's; width makes the date and time fields narrower than usual. check is called when you click OK; returning an object keeps the box open, with the message given and the caret in the field that's wrong. It uses parseDay and parseTime only to see whether they work: 31/02/2026 is refused, and so is 25:00.

ask is given a copy of the appointment with each value turned into what the box shows: the date as 23/09/2026, the alarm and repeat as the names on their menus, and the count of repeats (or nothing). When the box closes, the same happens the other way. +v.count || null turns the Times field into a number, and an empty field (which + makes 0) into null, meaning "for ever".

Adding and changing

The diary page decides what a double-click means:

On an appointment, it changes that appointment. On something that belongs to another section - an anniversary, later in this chapter - it goes to that section, with the window's go:

which opens the entry's section, asks the section to show the entry (each section's own go) and chooses it. On an empty part of a day it adds an appointment on that day. (Not in the Year view, whose days are too small to aim at; clicking one there goes to its week, as in chapter 11.)

add and edit are nearly the same: show the box with an appointment - a new one with just a date, or the one being changed - and if you clicked OK, add or update it. There's no need to redraw anything: the diary is a Collection, which emits 'change', and the window listens for that and redraws (chapter 10). After the box closes, this.org.focus() gives the input focus back to the binder, so the keys work straight away.

newEntry is what the window calls for the Insert key, the New entry menu item and the new button at the top of the toolbox: add an appointment on the day you're looking at. The Address section already had a newEntry, which adds a person (chapter 10), so the same key, menu item and button work there too. describe and remove are for deleting, which comes shortly.

Repeats

A weekly meeting could be written into the diary 52 times, but then moving it would mean changing 52 appointments. Instead, a repeating appointment is kept once, with a repeat saying how often, and the diary works out which days it falls on whenever it's drawn:

occurrences(from, to) is what the views ask for: every appointment on the days from from to to, each with the day it falls on (so one weekly meeting can appear four times in a month), sorted by date and then time. Because keys and times both sort as text, gluing them together ('2026-09-21' + '09:30') gives something that sorts by both at once.

datesOf does the work for one appointment. One that doesn't repeat is on one day or none. For a repeating one, STEP gives the function that goes on by n steps: D.addDays for daily, D.addMonths for monthly and so on - chapter 11's functions, with weekly made from addDays. The loop counts n up from 0, and stops when the date passes to, when it has happened count times or when it passes the date until; dates before from are counted but not kept. The last line is a guard: a daily appointment started years ago would still finish, but if a mistake ever made the dates stop moving, the loop couldn't run for ever.

Notice that each date is worked out from the first date, step(a.date, ++n), not from the one before. It matters for months. Something on the 31st of each month falls on 28 February, because there is no 31st; if March's date were worked out from February's, it would be the 28th too, and so would every month after. Worked out from the start, March is back on the 31st. That's the kind of thing to write down as a test before trusting it, and Check has grown some:

Look at the month view: the Monday team meeting and the Wednesday choir practice appear every week, from one entry each.

Choosing and deleting

To delete an entry you first say which: click it, and it's outlined. Choosing works the same in every section, so it's in Tools, not in the diary:

org.selected is the chosen entry's ref: { section: 'diary', id: 4, date: '2026-09-21' } say. Every section records a box for each entry it draws (chapter 10), so clickEntry only has to ask the section what's at the point clicked. It returns false, so the window goes on to give the click to the section as well (the diary also makes that day the chosen day):

When the window has drawn a section, it calls decorate to outline the chosen entry. A repeating appointment has one box for each day it's shown on, but the ref of each box includes its date, so only the one you clicked is outlined: two refs are the same if they have the same section, id and date (an entry with no date gives '' for both).

Deleting is the Delete key (or Backspace), the Delete menu item or a click on the wastebasket:

If nothing is chosen, beep says so. Otherwise remove finds the section the entry belongs to - which needn't be the one on show: the diary shows anniversaries too, as you'll see - and, unless prefs.confirm says not to (chapter 16's choices can turn it off), asks first. query is the desktop's question box: it shows the message and buttons and resolves to the name of the button clicked. The question needs a line about the entry, and only its section knows how to write one; that's describe. Then the section's remove deletes it.

Deleting a repeating appointment deletes all of it, every week: the question shows the date you clicked, but there's only one entry to delete. (A diary program with more time could ask "just this one, or all of them?" and keep a list of the dates left out.)

Dragging

The window's work area has been reporting drags since chapter 10 (workButton: 'clickdragdouble'), and now something listens:

If the drag didn't start on an entry, the section is given it, in case it wants to do something else (none does yet). Otherwise wimp.drag drags a dotted box the size of the entry, following the pointer, the way the Filer drags a file's box. It needs the box in screen coordinates, so the entry's position in the work area is turned into one with workToScreen. It's an async function: it resolves when the button is let go, with where that was - the window and icon under the pointer, and x and y in that window's work area - plus whether Shift or Ctrl was held down.

Dropped on the wastebasket - the icon called bin in the toolbox, which is a pane of its own - the entry is deleted, just as if it had been chosen and the wastebasket clicked. Dropped anywhere on the binder, the section is asked to put the entry there:

dayAt (chapter 11) says which day is under the point. A repeating appointment moves as a whole, by the same number of days as the one you dragged: drag Monday's meeting to Tuesday and it's on Tuesdays from then on, from its first week. The shift is worked out from ref.date, the day you dragged it from, and then applied to a.date, the day it started.

Dropping anything else - an anniversary, from its flag in the diary - does nothing: an anniversary's day is its date, and it belongs to its own section.

Anniversaries

Anniversaries are the simplest entries: a date and some text. The date is the one it all began - a birthday's is the day someone was born - so the organiser can work out how many years it has been.

inMonth and onDay ignore the year: a.date.slice(5, 7) is the month ('03', which + turns into 3), and slice(5) is the month and day, '03-14', the same every year.

nth gives the English for how many years: 1st, 2nd, 3rd, then 4th to 20th, then 21st, 22nd, 23rd, and so on. ['th', 'st', 'nd', 'rd'][n % 10] looks up the last digit; for 4 to 9 there is nothing in the list, and ?? gives 'th'. 11, 12 and 13 are the exceptions (11th, not 11st), and so are 111, 112 and so on, which is why the test is on n % 100.

Summary

  • The dialogue boxes for entries are in one module, Entries, made with Form, each made once and kept in a Map.

  • A list of [name, value] pairs turns menu choices into values and back. ([, x]) => skips the first item of the argument; list?.[0] is list[0], or undefined if there is no list.

  • A repeating appointment is kept once; its dates are worked out when they're needed, each from the first date, so the 31st of the month comes back after February.

  • Choosing, deleting and dragging are written once, in Tools, for every section. Each section records boxes for what it draws, and answers describe, remove and dropped.

  • wimp.drag drags a box and resolves with the window, icon and point where it was dropped. query asks a question and resolves with the button clicked.

  • A program's own sprites are loaded from a file with sprites.spritesFromFile and given to the Toolbar as its area.

  • A ref names its section, so one section can show another's entries.

Exercises

1 Add "Every fortnight" to the Repeat menu.

2 Show an appointment's end time in the diary, as Choir practice (to 21:00).

3 Make a drag with Shift held down copy an appointment to the day it's dropped on, rather than move it. (A copy is a new entry, so it mustn't keep the old one's id.)

4 The Store already understands repeat.until, a last date. Add a field for it to the Appointment box.

Answers

1 Add the pair to REPEATS in Entries: 
['Every week', 'week'], ['Every fortnight', 'fortnight'],
and a step to STEP in Store: 
fortnight: (k, n) => D.addDays(k, 14 * n),
Without the step, datesOf's ?? STEP.week would show it every week.

2 In itemsOn, give the appointment's text as 
text: appt.text + (appt.end ? ` (to ${appt.end})` : ''),
3 In Tools's drag, pass Shift on: 
org.section.dropped(box.ref, drop.x, drop.y, drop.shift);
and in DiaryPage's dropped(ref, x, y, copy), in place of the update: 
const date = D.addDays(a.date, shift);
if (copy) {
  const { id, ...fields } = a;       // all but the id
  doc.diary.add({ ...fields, date });
} else doc.diary.update(a.id, { date });
{ id, ...fields } = a takes id out and puts everything else in fields (the rest, as in appendix A). add then gives the copy a new id.

4 In editAppointment, add a field after Times: 
{ name: 'until', label: 'Last day', width: 120 },
check it in check: 
if (v.until && !D.parseDay(v.until)) return { field: 'until',
  message: 'Give the date as 25/09/2026' };
show it in ask with until: showDay(a.repeat?.until), and keep it: 
repeat: every ? { every, count: +v.count || null,
  until: D.parseDay(v.until) } : null,
parseDay gives null for an empty field, so there's no last day.
