The toolkit is the set of small modules you build in this book and share between the applications. Each lives in the book's toolkit directory and is copied into every application that uses it, as a file in its Toolkit directory; the application's Toolkit.list names the ones it needs. Import one from a module of the application like this:

import { ListView } from './Toolkit/ListView';
Once a module has been written it doesn't change: later chapters only use it. The chapter that builds each is given in brackets.

Emitter (1)

Lets one part of a program tell others that something has happened, without knowing who is listening. The models (Book, the organiser's collections), ListView, Form and Undo are all Emitters.

class Book extends Emitter { ... this.emit('change', c); }
const off = book.on('change', (c) => redraw());
off();                          // stop listening
on(type, fn)
Calls fn(data) whenever the event happens; returns a function that stops it.

emit(type, data)
Tells every listener.

ListView (2)

A list of rows to choose from, filling a window, with the Style Guide's selection rules: Select chooses one row, Adjust adds or removes one, double-click (or Return) opens, Menu over an unselected row selects it just for the menu. Up, Down, Home, Copy (End), Page Up and Page Down move when the window has the input focus.

const list = new ListView(w, {
  columns: [{ title: 'Name', width: 200, text: (c) => c.name }],
  key: (c) => c.id,          // what tells one item from another
  top: 44,                   // room above it (a toolbar)
});
list.setItems(book.list());
list.on('open', (c) => edit(c));
setItems(items)
Shows these items, keeping the selection of any that are still there.

selected(), isSelected(item)
The selected items, in list order; whether one is selected.

select(item, only = true), selectAll(), clear()
Change the selection (only false adds to it).

ensureVisible(item)
Scrolls so the item can be seen.

endTemporary()
Forgets a selection made just for a menu, when the menu closes.

Events
'select' (the selected items), 'open' (the item), 'menu' ({ ev, temporary }), 'drag' (the drag event, started on the selection).

Form (3)

A dialogue box made from a list of fields, with the buttons along the bottom right: the last one is the default, which Return presses; Escape presses Cancel. Return moves from field to field until the last.

const form = new Form(task, {
  title: 'Contact',
  fields: [
    { name: 'first', label: 'First name' },
    { name: 'notes', label: 'Notes', lines: 3 },
    { name: 'kind', label: 'Kind', choices: ['Home', 'Work'] },
    { name: 'vip', label: 'Favourite', option: true },
    { column: 2 },           // the fields after it: a new column
  ],
  buttons: ['Cancel', 'Save'],
  check: (v) => (v.first ? null
    : { field: 'first', message: 'Please give a name' }),
});
const values = await form.ask({ first: 'Ann' });   // or null
Field options
name, label, width, maxLen, help; allowed (the characters that may be typed, as an A validation string); lines (several lines: a TextArea); choices (a pop-up menu); option (an on/off option icon); { column: 2 } starts a second column.

Box options
title, message (a line above the fields), buttons (default ['Cancel', 'OK']), check(values) (null, or { field, message }: the problem is reported and the caret put in that field), stay (buttons that don't close the box: they emit 'button', as Choices' Default does), help.

ask(values), run(values)
Open the box. ask resolves the new values, or null for Cancel; run resolves { button, values }, or null.

get(), set(values)
Read or fill in the fields.

Toolbar (5)

A pane of 3D buttons across the top of a window, or down its left side like Draw's toolbox (chapter 11). The pictures come from the program's own sprite area.

const bar = new Toolbar(w, {
  area,                                // the program's sprites
  buttons: [
    { name: 'new', sprite: 'tb_new', help: 'Click SELECT to add',
      action: () => add() },
    { gap: true },
    ...
  ],
  search: { help: '...', change: (text) => find(text) },
  menu: (ev) => openMenu(ev),          // Menu clicked on it
});
bar.shade('delete', true);
Options
area, buttons ({ name, sprite, text, help, action, w, h } or { gap: true }), search (a Find field: { help, change, width }; Escape clears it), menu, side: 'left' and width for a toolbox down the left.

height, width
How much of the window it covers (start the list below it with ListView's top).

shade(name, on), hide(name, on), setText(name, text), setSprite(name, sprite), icon(name)
Grey a button out, take it away, change its text or picture, or get its icon.

search, pane
The Find field's icon, and the pane window itself.

Formats (8)

Swapping contacts with other programs. A contact is an object with the fields in FIELDS (title, first, last, company, job, address, postcode, work, home, mobile, email, web, birthday, category, notes).

vcardWrite(contacts) -> text      vCard 3.0, a card after another
vcardRead(text)      -> contacts  vCard 2.1 or 3.0
csvWrite(contacts)   -> text      a header row, then a row each
csvRead(text)        -> contacts  columns matched by their titles
csvRows(text)        -> rows      the cells of a CSV file
decode(bytes) -> text   UTF-8 (or Latin-1) bytes to RISC OS text
encode(text)  -> bytes  RISC OS text to UTF-8
fullName(c)            'Ann Smith', or the company
fold(line)    -> text   a long line folded at 75 octets (vCard,
                        and ICal uses it too)
What exactly is read and written is in appendix E.

Undo (9)

Remembers changes so they can be undone and redone. Each change is a command: an object that knows how to make the change and how to take it back.

const undo = new Undo();               // (limit: 50 changes)
undo.do({ name: 'Delete',
  do: () => book.remove(c.id), undo: () => book.put(c) });
undo.undo();  undo.redo();  undo.clear();
undo.canUndo  undo.canRedo  undo.undoName  undo.redoName
undo.on('change', () => shadeMenus());

Binder (10)

Draws a ring binder on a window's canvas: a coloured cover, two pages side by side with the rings between them, section tabs down the right-hand edge and turned-up corners to turn the pages. It only draws and measures: what a click does is up to the program.

const binder = new Binder({ x, y, w, h, colour: '#6b3f22',
  tabs: [{ name: 'Diary', colour: '#4f81bd' }, ...] });
binder.draw(g, current);     // current: the open section's tab
binder.left, binder.right    // the pages: { x, y, w, h }
binder.hit(x, y)             // { tab: 2 }, { corner: -1 } (back),
                             // { corner: 1 } (on), { page: 'left' },
                             // { page: 'right' } or null

Dates (11)

Days written as keys, '2026-09-25': they sort and compare as text, make good names for things in a Map, and go into files as they are. JavaScript's Date is used only inside the module, always at midday, so that changes to and from summer time never move a day. Weeks start on Monday.

today()                       '2026-09-25'
keyOf(date), dateOf(key)      a Date to a key and back
addDays(key, n)  addMonths(key, n)  addYears(key, n)
daysBetween(a, b)             whole days from a to b
weekday(key)                  0 Monday ... 6 Sunday
startOfWeek(key)              the Monday of its week
daysInMonth(year, month)      months are 1-12 here
monthGrid(year, month)        6 weeks x 7 keys, Mondays first
parseDay('25/12/2026')        a key, or null ('2026-12-25' too)
parseTime('9:30')             '09:30', or null
format(key, '%W3 %ZDY %M3')   the desktop's formatTime codes
addMonths keeps to the end of a short month: 31 January plus one month is 28 (or 29) February.

ICal (16)

Swapping appointments and things to do with calendar programs, in iCalendar files (appendix E).

icalWrite({ events, todos }) -> text
icalRead(text)               -> { events, todos }
An event is { date, time, end, text, alarm, repeat } (alarm: minutes before, or null; repeat: { every: 'day' | 'week' | 'month' | 'year', count, until } or null); a to-do is { text, due, start, priority, done, category }, with priority 1 (high) to 3.
