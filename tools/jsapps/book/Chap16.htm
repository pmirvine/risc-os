The organiser from chapter 15 already keeps a diary, things to do, addresses, notes, a year planner and anniversaries. This chapter adds what turns it into a finished application: alarms that remind you of appointments, a Find that looks in every section, printing, swapping entries with other programs, and choices you can change. At the end is the finished !Organiser, a tour of it, and some ideas for taking it further.

Reminders

An appointment can have an alarm: At the time, or 5 minutes, 15 minutes, an hour or a day before, chosen in the appointment's dialogue box (chapter 12) and kept as a number of minutes. Until now nothing looked at it. RISC OS has its own alarm program, !Alarm, and the Organiser's alarms work the same way: at the right time a box appears with the appointment in it, and two buttons - OK, and Snooze to be reminded again in five minutes.

The plan

A desktop program can't sit in a loop waiting for the time to come round (book 1, chapter 9). Instead it asks to be called now and then with task.every, and each time looks at the clock:

1 Every ten seconds, go through the appointments today and tomorrow in every open organiser.

2 Work out when each one's alarm goes off: its time, less the alarm's minutes.

3 If that time has come, and the alarm hasn't been shown yet, show it.

Two things need remembering: which alarms have been shown (so each appears once), and which have been snoozed (so they come back later). An alarm is named by its document, its appointment and its date together - a repeating appointment has an alarm on every day it happens. The document is given a number of its own for this rather than using its filename, which changes when an untitled document is saved.

One more rule, from !Alarm: an alarm more than an hour old has been missed (the computer was off, say) and isn't shown. Without it, opening an organiser in the evening would bring up every alarm of the day at once.

The Reminders module

done is a Set of the names of alarms already shown, and snoozed a Map from an alarm's name to the time it should come back. check asks each open document's diary for the occurrences of appointments from today to tomorrow - the same method the Diary pages use to draw repeating appointments (chapter 12) - so repeats get their alarms too.

idOf hands out those numbers, keeping them in a WeakMap (a Map that lets go of a document once it's closed). alarmTime builds a Date for the day and sets its hours and minutes with setHours(h, m, s, ms), which takes the hours and, optionally, the minutes, seconds and milliseconds. For an appointment at 09:10 with a 15-minute alarm, the minutes are 10 - 15, which is -5. setHours doesn't mind: it carries the minutes over, and the time becomes 08:55. Letting Date do the carrying is much simpler (and safer) than doing it yourself.

show uses a Form with no fields at all - just a message and two buttons - as a small alarm box, and sounds the bell with beep. run waits for a button; if it was Snooze, the alarm gets a new time five minutes on and is taken out of done, so a later check shows it again.

Printing

The toolbox's printer button (and the Print key, and Menu > File > Print pages) prints the two pages showing. The pages are drawn by one method, org.draw(g), whatever g is - so printing them only needs a canvas of their own to draw on:

document is the desktop's object for making things like canvases, and document.createElement('canvas') makes a canvas that isn't in any window: a sheet of paper the program can draw on without anything appearing on the screen. It's made the size of the binder, and translate moves the drawing so the binder's corner is at its top left. Then the canvas goes to !Printers, which prints it on the printer chosen there (see appendix C). A Notepad page's text is on the text area's own canvas (chapter 14), not drawn by org.draw, so drawImage copies it onto the sheet in its place.

Printing needs !Printers to be running, as it does for every RISC OS program. If it isn't, os.printers is missing, and the Organiser says what to do rather than failing.

Note: this is the first time drawing code has been used for two things - the screen and the printer. It works because draw only draws: it doesn't change anything or depend on the window. Keeping drawing like that pays off.

Swapping with other programs

Most calendar programs can read and write iCalendar files (.ics). The last toolkit module, ICal, handles a small part of the format: appointments (VEVENT), things to do (VTODO), repeats and alarms. Appendix E describes exactly what it writes and reads. This is how an appointment goes out:

BEGIN:VEVENT
UID:1790371712345-1@organiser
DTSTAMP:20260925T093000Z
DTSTART:20260926T123000
DTEND:20260926T133000
SUMMARY:Lunch with Bob
BEGIN:VALARM
ACTION:DISPLAY
DESCRIPTION:Lunch with Bob
TRIGGER:-PT15M
END:VALARM
END:VEVENT
Each line is a name, a colon and a value; BEGIN and END bracket an entry. It's the same idea as vCard (chapter 8), and icalWrite is written the same way, pushing lines onto an array:

Times are written as 20260926T123000 - the date, a T, and the time - by the small functions day and at at the top of the module; DTEND, the end time, goes out only if the appointment has one. DTSTAMP, which iCalendar asks for in every entry, says when the file was made, in UTC (the Z): toISOString gives 2026-09-25T09:30:00.000Z, and stamp takes out the dashes, colons and milliseconds. A repeat becomes an RRULE such as FREQ=WEEKLY;COUNT=10 - or, if it has an end date, UNTIL written the same way as DTSTART, but never both. An alarm becomes a VALARM whose TRIGGER is the alarm's minutes before. iCalendar's priorities go from 1 to 9, so the Organiser's 1, 2 and 3 go out as 1, 5 and 9. Every line is folded at 75 characters, as vCard's are, by importing fold from chapter 8's Formats rather than writing it again.

!Organiser's Toolkit.list gains two lines: ListView, for Find's results, and ICal.

Reading, in icalRead, uses destructuring in two new ways. Destructuring can assign as well as declare: with no const or let in front, it puts the array's items into variables or properties that already exist - here setting two properties at once:

[item.date, item.time] = when(value);
and, as in chapter 12's answer 3, rest in destructuring collects everything not named into a new object:

const { kind, date, time, end, ...rest } = item;
Here rest is item without those four properties - just right for a to-do, which has no date or time of its own. (Appendix A has both.)

Choices

The Organiser's choices follow chapter 9's pattern exactly: a Choices... item on the icon bar menu, a dialogue box with Default, Cancel, Set and Save, and the settings kept with choices.read and choices.write in Choices:Organiser. There are two: the colour of the binder's cover, and whether to ask before deleting.

The box shows a colour's name (Brown) while the program keeps the colour itself ('#6b3f22'); nameOf finds the name for a colour, and shown turns the settings into what the box shows, as shown did in Contacts. The finished organiser

That completes !Organiser. Here is what it does, and the chapter that added each part:

  • A ring binder: coloured section tabs, turned-up page corners, pages drawn as paper (chapter 10). Its own file type, &1C5, holding every section in one file, and several files open at once (chapter 10).

  • The Address section: Contacts' own Book and card, reused unchanged (chapter 10).

  • A diary with year, month, week and day views, moved about with the keys, and the toolbox down the left (chapter 11).

  • Appointments that repeat and can be dragged to another day, anniversaries, and the wastebasket (chapter 12).

  • Things to do, with priorities and due dates, shown in the diary (chapter 13).

  • A notepad, links between entries, and Back (chapter 14).

  • A year planner painted with coloured, patterned bars (chapter 15).

  • Alarms, Find, printing, iCalendar and vCard, choices and help (this chapter).

The Check program has grown with it: it now tests the alarm times and that an appointment and a to-do come back from iCalendar exactly as they went out. Run it after any change to the parts that don't need windows.

Going further

The Organiser is yours to change. Some ideas, roughly from easiest to hardest:

A choice of first day of the week
The diary's weeks start on Monday (startOfWeek in Dates). Some people want Sunday. That's a third choice, and a parameter for startOfWeek.

A Calls section
Lotus Organizer added one in its second version: a log of telephone calls - who, when, what about, and whether to call back. It's a new Section subclass, a collection in Store, and a seventh tab. Everything else - saving, Find, links, the wastebasket - works through the section interface.

Sections of your own
Let the user add sections: a second to-do list for a project, say, with a name and a tab colour chosen in a dialogue box.

Printing refill pages
Print a week on a page the size of an organiser refill (a Filofax "personal" page is 95 by 171 millimetres), with the days laid out as the paper is ruled.

Keeping in step with another calendar
Export to iCalendar, import from it: that's all a simple sync is, if each entry keeps the UID it had in the other program, so it can be matched up next time.

The end of Part Two

Over these seven chapters the Organiser has used everything from Part One - the model and its events, the list, forms, the toolbar, documents, formats and choices - and added what a bigger application needs: a common interface for its sections, so one window can hold six different kinds of page; dates; drawing a whole interface on a canvas; and working with the rest of the desktop and other programs.

Chapter 17 is a last look under the bonnet: how a text area like the Notepad's works, by building one.

Summary

  • Alarms are checked with task.every: work out each alarm's time, show it once, snooze by giving it a new time. Old alarms are missed, not shown.

  • Date's setHours carries minutes and hours over, so time arithmetic can be left to it.

  • Find is shared out: each section has a find method returning results with a ref, and a ListView shows them.

  • Drawing code that only draws can draw on a canvas of its own - document.createElement('canvas') - to print through !Printers with os.printers.print({ title, canvas }).

  • iCalendar is lines of NAME:value, like vCard; toolkit/ICal reads and writes appointments, to-dos, repeats and alarms (appendix E).

  • Dropped files are recognised by what's in them.

  • Destructuring can assign to existing variables and properties, and ...rest collects what's left of an object.

Exercises

2 Make Find ignore entries in the diary more than a year ago.

3 Add Menu > File > Export > Addresses (CSV), using csvWrite from chapter 8.

4 The alarm box doesn't say which organiser the appointment is in. Add the file's leaf name to its message when more than one organiser is open.

5 Add the first-day-of-the-week choice described in Going further.

Answers

1 Add a field to the Choices form, { name: 'snooze', label: 'Snooze', choices: ['5', '10', '15'] }, a default of snooze: 5 in DEFAULTS, and store it as a number. Then in Reminders use it in place of SNOOZE: 
const mins = this.app.prefs.snooze ?? SNOOZE;
this.snoozed.set(name, new Date(Date.now() + mins * 60000));
2 In DiaryPage's find, filter on the date too. Day keys compare as strings, so: 
const since = D.addYears(D.today(), -1);
return this.doc.diary.all()
  .filter((a) => a.date >= since &&
    a.text.toLowerCase().includes(t))
3 In exportMenu, import csvWrite too and add 
{ text: 'Addresses (CSV)', submenu: box('Cards/csv', 0xDFE,
  () => csvWrite(doc.book.all())) },
4 check knows the document (doc); pass it to show and add vfs.leaf(doc.filename) to the message when this.app.docs.size > 1 (import vfs from 'riscos').

5 Give startOfWeek a second parameter, the first day, counted as weekday counts (0 for Monday up to 6 for Sunday), defaulting to Monday: 
export const startOfWeek = (key, first = 0) =>
  addDays(key, -((weekday(key) - first + 7) % 7));
Add week: 'Monday' to the choices, and pass prefs.week === 'Sunday' ? 6 : 0 wherever the Diary calls startOfWeek, and change the days' names along the top of the week and month views to match. Don't forget the month grid, which starts its rows on the same day.
