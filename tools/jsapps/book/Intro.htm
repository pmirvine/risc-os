This book carries on where Programming in JavaScript left off. That book taught you the language and how to make RISC OS do things: windows, drawing, the mouse and keyboard, menus, the icon bar, modules and files, ending with a game. This one teaches you to write applications: programs that people use to look after their own information, day after day, the way they use Draw or Edit.

Who this book is for

You should have worked through Programming in JavaScript (it's in HardDisc4.$.Manuals.JSTutor), or know the same things another way: variables, loops, functions, arrays and objects, modules with import and export, making a window with task.createWindow and drawing in it, menus, and reading and writing files. Where this book uses something that book didn't cover, it explains it when it first appears; appendix A gathers the new parts of the language together.

What you will build

Part One builds !Contacts, an address book. It keeps names, addresses, telephone numbers and so on; shows them in a list you can search and sort; has a dialogue box for each person's details and a toolbar across the top of its window; saves address books in files of their own type, several at once; swaps addresses with other programs as vCard and CSV files; and can undo what you do. It follows the rules Acorn set for well-behaved applications, so it feels like part of RISC OS.

Part Two builds !Organiser, a personal organiser in the spirit of Lotus Organizer, the best-selling organiser of the 1990s. Its window looks like a ring binder open on the desk, with coloured tabs down the edge for its sections: a diary, a list of things to do, the address book (the one from Part One, reused without changing a line), a notepad, a year planner and a list of anniversaries. There's a toolbox down the left, like Draw's, with a wastebasket you can drag things into.

Along the way you will learn how real applications are put together: how to plan one, how to keep the information a program looks after apart from the windows that show it, how to make lists, dialogue boxes and toolbars, how to handle documents and file types, and how to test what you've written.

How the book is arranged

  • Chapters 1 to 9 (Part One) build !Contacts, one feature at a time.

  • Chapters 10 to 16 (Part Two) build !Organiser, starting with the binder and its sections and ending with reminders, printing, and sharing appointments and to-dos with calendar programs through iCalendar files.

  • Chapter 17 is a little extra: the notepad in !Organiser uses a multi-line text box the desktop provides, and in chapter 17 you build a simple one of your own to see how such a thing works.

  • The appendices are references: more JavaScript, the toolkit's modules, the parts of the desktop the book uses, a checklist of the Style Guide's rules, and the file formats.

Each chapter ends with a summary, exercises and answers, as in the first book.

The example applications

Every chapter ends with a complete, working application, and all of them are in HardDisc4.$.Examples.JSApps. The one for chapter 1 is !Contacts1, chapter 2's is !Contacts2 and so on; the finished address book is !Contacts and the finished organiser !Organiser. Each stage is the one before with just that chapter's changes, so you can open two of them side by side in JsEdit and see exactly what changed.

Double-click an application to run it. To look inside, Shift-double-click it: its directory opens, and you can Shift-double-click each file to read it in JsEdit. As with the first book, copy an application somewhere of your own before changing it.

The toolkit

Some parts of an application are needed again and again: a list to choose from, a dialogue box made of fields, a toolbar. Rather than write them afresh each time, you will build a small toolkit of modules and use it in both applications:

Emitter
lets one part of a program tell others that something has happened (chapter 1).

ListView
a list of rows to choose from (chapter 2).

Form
a dialogue box made from a list of fields (chapter 3).

Toolbar
a row of buttons along the edge of a window (chapter 5).

Formats
reading and writing vCard and CSV files (chapter 8).

Undo
remembering what was done, so it can be undone (chapter 9).

Binder and Dates
the organiser's binder, and working with dates (chapters 10 and 11).

ICal
reading and writing iCalendar files, the calendar programs' format (chapter 16).

Each module is short enough to read in one sitting, and once a chapter has built it, it doesn't change: the later chapters only use it. Each application keeps its own copy of the modules it uses in a directory called Toolkit inside it, so every application is complete in itself. The desktop itself provides everything else - windows, icons, menus, the Save box and so on - just as it did in the first book.

The Style Guide

In 1993 Acorn published the RISC OS 3 Style Guide, a book of rules for how applications should look and behave: where the buttons go in a dialogue box, what Return and Escape do, how a program shows that a document has been changed, which function key saves, and many more. Applications that follow it feel familiar at once, because everything works the way it does everywhere else. This book follows the Style Guide and quotes it where it matters; appendix D is a checklist of its rules.

Writing the programs

Use JsEdit (in HardDisc4.$.Apps), as in the first book: its line numbers, colouring, completion and throwback make the larger programs here much easier to work on. An application's modules are JSScript files inside its directory; to run the application, double-click its directory, or use JsEdit's Run button on its !RunImage.

Conventions

As in the first book: program text is shown like this; the mouse buttons are Select, Menu and Adjust; Menu > Sort > Surname means click Menu, move to Sort, then choose Surname. Listings often show part of a file, with its line numbers in the text (for example "lines 12 to 20 of Model"): use JsEdit's line numbers, or F5, to find them.
