So far Contacts has had one address book, made up by the program each time it starts. In this chapter it becomes a proper RISC OS application: its address books are files with a file type and an icon of their own, you can save them, double-click them to open them, have several open at once, and it asks before throwing away changes you haven't saved. The program for this chapter is !Contacts7.

A file type of its own

On RISC OS a file's type decides what happens when you double-click it: Text files open in Edit, Sprite files in Paint, JSScript files run. An address book should open in Contacts, so Contacts' files need a type of their own.

A file type is a number from 0 to &FFF. Most are taken - Text is &FFF, Draw files &AFF - and real applications ask RISC OS Open to allocate them one, so that two programs never use the same number. For this book we use &1C4, a number no other program on this desktop uses, and call it Contacts.

Two system variables tell RISC OS about a file type:

File$Type_1C4
its name, which the Filer shows (in Info and full info displays) and which Set type understands.

Alias$@RunType_1C4
the command that runs when a file of that type is double-clicked, with the file's name added to the end.

They are set in the application's !Boot file, an Obey file which the Filer runs the first time it shows the application in a directory display - so as soon as you have seen !Contacts7, its files know where to go:

IconSprites loads the application's sprites, which now include file_1c4 and small_1c4: the Filer shows files of type &1C4 with the sprite called file_ and the type's number. The last line makes double-clicking a Contacts file run !Contacts7.!Run with the file's name after it.

The %% needs explaining. In an Obey file, %0 to %9 and %*0 stand for the parameters the Obey file itself was run with, and are replaced before each line is carried out. We don't want that here: the alias should contain the characters %*0, to be replaced later by the name of the file being double-clicked. %% in an Obey file stands for one %, so %%*0 becomes %*0 when the line runs. !Run uses a plain %*0, because there it does mean its own parameters - the file being opened - which it passes on to !RunImage:

Whichever the Filer showed last is the one a double-click starts. To be sure which one opens a file, start it first and drag the file onto its icon on the icon bar.

An address book as text

A file holds text (or bytes). As Doodle did in book 1, Contacts turns its data into text with JSON. The Book class gains two methods:

toJSON is a name JSON.stringify knows: when it meets an object with a toJSON method, it turns into text whatever that method returns instead of the object itself. A Book holds its contacts in a Map, which JSON can't show, so toJSON gives back a plain object holding an array of them.

fromJSON goes the other way. The word static in front of it makes it belong to the class itself rather than to each book: you call it as Book.fromJSON(data), before there is a book, and it makes one.

The object saved has two fields besides the contacts:

  • format: 'Contacts' says what the file is, so fromJSON can refuse a file that isn't an address book (someone could set any file's type to Contacts) with a clear message rather than something baffling later.

  • version: 1 says which version of the format it is. If a later Contacts saves more - a photograph, say - it can write version 2, and still read version 1 files by looking at this number first. It costs nothing to put in now, and it's very hard to add later, when there are files without it.

 "version": 1,

Documents

With several address books open, each needs its own Book, its own window, the name of its file, and a note of whether it has changed since it was saved. A class called Document keeps those together - one Document for each open file:

The constructor makes the document's window (MainWindow now takes the document rather than the book, and reaches the book as doc.book), and listens to the book: any change at all marks the document as modified. app.docs is a Set of the open documents. A Set is like an array that holds each thing once, with add, delete and has; appendix A has more.

load is another static method: it reads a file, turns it back into a Book and makes a Document for it. It is async, because reading a file is.

The title bar

The RISC OS Style Guide asks for a document's window to show its file's full name, and a * after it from the moment it is changed until it is saved - so you can always see what would be lost. get title() is a getter: doc.title looks like a property, but reading it runs this function, so it is always up to date. setModified asks the window to show the new title (updateTitle in MainWindow is one line: this.win.setTitle(this.doc.title)).

save writes the file with type &1C4, remembers its full name, and clears the *. JSON.stringify(this.book, null, 1) calls the book's toJSON as described above.

Saving

saveBox makes the desktop's standard Save box, which you used in book 1: drag its icon to a directory display, or type a full name and click OK. The window's menu has File > Save, with the Save box as its submenu, as in every RISC OS application.

quickSave is what F3 and the Save button do: a document that already has a file is saved to it straight away; a new one opens the Save box. Both take an optional function, then, to call once the document has been saved - you'll see why in the next section.

Closing

When you close a window whose document has changes that haven't been saved, the Style Guide's rule is to ask, with three buttons: Discard (close it anyway), Cancel (don't close it) and Save. MainWindow stops the window closing by itself, and asks the document instead:

ev.preventDefault() stops the Wimp's usual action - closing the window - so the document can decide:

The box is a Form from chapter 3 with no fields, a message and three buttons. The last button, Save, is the default, so Return saves; Escape (or Cancel) gives null. If you choose Save, the document is saved with quickSave and closed afterwards, by the function passed as then - after the Save box, if it hasn't a file yet. If that Save box is abandoned, the document stays open, which is just what you'd want.

dispose tidies up: it deletes the window (and stops it listening to the book) and takes the document out of app.docs.

One Contacts, several books

Because there can now be several address books, there should be only one Contacts: double-clicking a second file should open it in the Contacts already running, not start another copy. The start of !RunImage sees to that:

A program started with a file - by a double-click, or by dragging it to the application - finds the file's name in ctx.argv[0], the first word of what !Run passed on. (Don't confuse it with ctx.file, which is the full name of the program itself.)

wimp.tasks is the list of every task running on the desktop. If one of them is another Contacts, this copy sends it the file in a DataOpen message - the message the Filer itself sends when a file is double-clicked - and quits at once.

Trying it

1 Open HardDisc4.$.Examples.JSApps and double-click !Contacts7. Its icon appears on the icon bar; nothing else happens, as it wasn't given a file.

2 Drag Friends onto the Contacts icon. The address book opens.

3 Click Select on the Contacts icon: a new, empty book opens. Add a contact; a * appears in its title.

4 Press F3, and drag the Save box's icon to a directory of your own. The file appears with the Contacts icon, and the * goes.

5 Change something again and close the window: the Discard/Cancel/Save box appears.

6 Double-click the file you saved. It opens in the Contacts that's running - check the Task Manager: there is still only one Contacts7.

Summary

  • A file type is a number; File$Type_xxx names it, Alias$@RunType_xxx says what double-clicking runs, and the file_xxx sprite is its icon. !Boot sets them.

  • In an Obey file %0-%9 and %*0 are its parameters; %% is a %.

  • A toJSON method decides what JSON.stringify saves; a static method belongs to the class. Put a format name and a version number in every file you design.

  • A Document class keeps one open file's data, name, modified flag and window together.

  • Show the file's name and a * while it is changed; save with F3 and the Save box; ask Discard/Cancel/Save before closing a changed document.

  • A file passed to a program arrives in ctx.argv[0]. The Filer offers a double-clicked file to running tasks with DataOpen first; claim it to open it in the running copy.

Exercises

1 Put the number of contacts in the title, after the file's name: Friends (10).

2 Add an item New book to the icon bar menu, doing what Select on the icon does.

3 fromJSON accepts any version. Make it refuse files whose version is greater than 1, with the message This file was made by a newer Contacts.

4 Quitting from the icon bar menu asks once about all the changed books. Change it so that it goes through them, closing each one with its own Discard/Cancel/Save box, and quits only if they all close.

Answers

1 The title is made in one place, the getter: 
get title() {
  const name = this.filename || '<untitled>';
  const full = `${name} (${this.book.size})`;
  return this.modified ? full + ' *' : full;
}
It changes whenever a contact is added or removed, because every change calls setModified.

2 Add { text: 'New book', action: () => new Document(app) } before Quit in menu.

3 In fromJSON, after the format check: 
if (data.version > 1) {
  throw new Error('This file was made by a newer Contacts');
}
4 close resolves true if the document closed: 
const quit = async () => {
  for (const d of [...app.docs]) {
    if (!(await d.close())) return;
  }
  task.quit();
};
([...app.docs] makes a copy, because closing a document takes it out of the set.) A document whose Save box is still open counts as not closed, so Contacts doesn't quit under it.
