A window is much more fun when you can draw in it. This chapter shows how to draw rectangles, lines, circles, triangles and text in any colour, and then uses a loop and a little trigonometry to draw a spirograph pattern that fits itself to the window.

The redraw function

You might expect a drawing program to draw its picture once, when it starts. On the desktop that isn't enough. Windows get covered up by other windows, dragged partly off the screen, scrolled and resized, and each time part of a window comes back into view, it has to be drawn again. The Wimp doesn't remember what was in your window: it asks your program to draw it again.

So instead of drawing once, you give the window a redraw function: a function that draws the whole picture, which the Wimp calls whenever the window needs drawing. You give it with w.useCanvas:

w.useCanvas((g) => {
  // draw everything here, using g
});
The function is given a graphics context, g: the thing you draw with. It has functions for drawing shapes and text, and settings such as the colour to draw in. (A canvas is the surface being drawn on, and g is the pen.) Positions are in the window's work area, with (0, 0) at the top left and y going down, as in chapter 6. The work area is cleared to its background colour before your function is called, so you always start with a blank page.

Shapes

This program draws one of each of the main shapes:

Rectangles

g.fillRect(x, y, width, height) draws a filled rectangle with its top-left corner at (x, y), in the colour g.fillStyle. g.strokeRect draws just the outline, in the colour g.strokeStyle, with lines g.lineWidth pixels thick.

The settings stay as they are until you change them, so once fillStyle is red, everything filled is red until you choose another colour. It's a good habit to set the colour just before each thing you draw.

Lines and paths

Everything other than a rectangle is drawn as a path: you start a path, describe its shape, then either draw along it (stroke it) or fill it in.

g.beginPath();          // start a new path
g.moveTo(320, 20);      // go to here without drawing
g.lineTo(420, 100);     // a line from there to here
g.stroke();             // draw the path's lines
You can add as many lineTos as you like, each carrying on from the last. The triangle is three points joined up; g.closePath() joins the last point back to the first, and g.fill() fills the shape in.

Circles

g.arc(x, y, radius, start, end) adds a circle, or part of one, to a path. (x, y) is the centre. start and end are angles in radians, the unit JavaScript uses for angles: a whole turn is 2 x pi radians, which is Math.PI * 2. So a whole circle goes from 0 to Math.PI * 2, and half a circle from 0 to Math.PI.

Text

g.fillText(text, x, y) writes text, in the fillStyle colour. (x, y) is the left-hand end of the text's baseline - the line the letters sit on - so the text is drawn above y. g.font chooses the size and style, as a string such as '20px sans-serif', 'bold 16px serif' or '14px monospace'.

Note: the desktop's own fonts work too: '20px Homerton', 'bold 20px Trinity', '16px Corpus', and the programming fonts "JetBrainsMono Nerd", "Hack Nerd" and "FiraCode Nerd" (in double quotes inside the string, because the names have a space in them). The last three are Nerd Fonts, which hold thousands of little icons as well as letters. An icon is a character with a number, written in a string as \u and four hexadecimal digits:

g.fillStyle = 'black';
g.font = '32px "JetBrainsMono Nerd"';
g.fillText('\uf121 \uf0e7 \uf1b0', 20, 60);   // code, lightning, paw
The icons can only be drawn by a program: they aren't characters you can type into JsEdit.

Colours

There are several ways to give a colour:

A name
'red', 'blue', 'orange', 'darkgreen', 'pink'... There are over a hundred.

Red, green and blue
'#ffcc00' gives the amount of red, green and blue as two hexadecimal digits each (counting in sixteens, with the letters a to f as the digits after 9, so ff is 255; chapter 8 says more), from 00 (none) to ff (full). '#ffcc00' is full red, a lot of green and no blue: a golden yellow.

Hue, saturation and lightness
'hsl(120, 80%, 45%)' gives the hue as an angle round the colour wheel (0 red, 120 green, 240 blue, back to red at 360), then how strong and how light the colour is. It's handy in loops, as you'll see in the next program.

A Wimp colour
wimpColour(n) gives one of the sixteen colours the desktop itself uses: 
 0 white          4 grey 4        8 dark blue     12 cream
 1 grey 1         5 grey 5        9 yellow        13 dark green
 2 grey 2         6 grey 6       10 light green   14 orange
 3 grey 3         7 black        11 red           15 light blue
These are the same numbers as the window colours in chapter 6, such as workBg: 0.

Patterns with loops

The computer never gets bored, so it's good at drawing things made of hundreds of pieces. This program draws a spirograph pattern out of 1400 short lines, each a slightly different colour:

The curve

The function curve works out a point on the pattern. As the angle t goes round and round, the point traces out the curve that a pen makes in a spirograph: a small wheel rolling round inside a big one, with the pen some way from the small wheel's centre. Math.cos and Math.sin are the cosine and sine functions, which turn an angle into a position round a circle. You don't need to follow the mathematics: try changing the numbers big, small and pen and see what happens. (If you make the pattern bigger, some of it may go off the edge.)

curve returns an object with two properties, x and y, which is a convenient way for a function to give back two numbers at once.

Drawing it

The redraw function goes round a for loop 1400 times. Each time, it works out two points next to each other on the curve, a and b, and draws a line between them. The colour is worked out from i, so the hue goes once round the colour wheel from the start of the pattern to the end:

g.strokeStyle = `hsl(${i * 360 / steps}, 80%, 45%)`;
The curve's points are small numbers, between about -9 and 9, so they're multiplied by size to make the pattern big enough to see, and added to the centre point (cx, cy) to put it in the middle.

Fitting the window

The redraw function is given a second parameter, r, as well as g. It describes the part of the work area you can see: r.x0 and r.y0 are its top-left corner and r.x1 and r.y1 its bottom right. The program works out the middle of that area, and a size to suit, so the pattern is always in the middle of the window and as big as fits.

This window has scroll bars and a size icon, and a work area much bigger than the window. Make the window bigger or smaller, or scroll it: each time, the Wimp calls the redraw function and the pattern is drawn to fit the new view.

Asking for a redraw

The Wimp calls the redraw function when it knows the window needs drawing. But when something in your program changes what the picture should look like, only your program knows. Then you ask for the window to be drawn again by calling:

w.invalidate();
This doesn't draw anything straight away. It tells the Wimp the window's picture is out of date, and the Wimp calls your redraw function soon afterwards, when it's ready. So all your drawing stays in one place, the redraw function, and the rest of the program just changes the information the picture is drawn from and calls invalidate. You'll do exactly this in the next two chapters, when the picture changes because of the mouse, the keyboard or the passing of time.

Note: if you make a mistake in the redraw function, you get an error box as usual, and the picture stops at the point where the mistake is. The box appears only once, even though the Wimp keeps asking for the window to be redrawn, so you aren't buried in error boxes.

Summary

  • The Wimp asks your program to draw its windows whenever they need it. w.useCanvas((g, r) => {...}) gives the function that does it; r is the part of the work area you can see.

  • fillRect and strokeRect draw rectangles. Other shapes are paths: beginPath, moveTo, lineTo, arc, closePath, then stroke or fill.

  • fillStyle, strokeStyle, lineWidth and font are settings that last until you change them. fillText draws text.

  • Colours can be names, '#rrggbb', 'hsl(...)' or wimpColour(n).

  • Angles are in radians: a whole turn is Math.PI * 2.

  • Call w.invalidate() when the picture needs drawing again.

Exercises

1 Draw a house: a square for the walls, a triangle for the roof, and rectangles for a door and two windows.

2 Draw a chessboard of eight by eight squares, using two for loops, one inside the other. (Hint: a square is black when (row + column) % 2 is 1.)

3 Draw twenty circles with the same centre, each a little bigger than the last, in the sixteen Wimp colours in turn.

4 Change Pattern's big, small and pen to 7, 4 and 5. What happens? (Hint: look at how far round t goes.)

Answers

1 For example, in a redraw function: 
  g.fillStyle = wimpColour(12);
  g.fillRect(100, 150, 200, 150);        // walls
  g.fillStyle = 'red';
  g.beginPath();
  g.moveTo(80, 150);
  g.lineTo(200, 60);
  g.lineTo(320, 150);
  g.closePath();
  g.fill();                              // roof
  g.fillStyle = 'brown';
  g.fillRect(180, 220, 40, 80);          // door
  g.fillStyle = wimpColour(15);
  g.fillRect(120, 180, 40, 30);          // windows
  g.fillRect(240, 180, 40, 30);
2 With squares 40 pixels across: 
  for (let row = 0; row < 8; row++) {
    for (let col = 0; col < 8; col++) {
      if ((row + col) % 2 === 1) {
        g.fillStyle = 'black';
      } else {
        g.fillStyle = 'white';
      }
      g.fillRect(col * 40, row * 40, 40, 40);
    }
  }
3 Draw the biggest first, so the smaller ones show on top of it: 
  for (let i = 20; i > 0; i--) {
    g.fillStyle = wimpColour(i % 16);
    g.beginPath();
    g.arc(200, 200, i * 8, 0, Math.PI * 2);
    g.fill();
  }
4 You get a different shape, but its colours look wrong: part of it is drawn twice, and the second pass paints over the first in other colours. The curve comes back to where it started when t has gone round small times, Math.PI * 2 * small (as long as big and small have no whole number that divides both, as 7 and 4 don't). With small as 4 that is Math.PI * 8, but the loop still goes to Math.PI * 14, so it draws the whole pattern and then three-quarters of it again. Change both Math.PI * 14s to Math.PI * 8 and it is drawn exactly once.
