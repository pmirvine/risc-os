In this chapter you will turn Doodle into a proper desktop application: it will have a menu, an icon on the icon bar, an Info box and a colour menu, and it will keep running when its window is closed, as Edit and Draw do.

Menus

Every RISC OS application has a menu, opened by clicking Menu over its window. In JavaScript a menu is made with new Menu(...), which is given the menu's title and a list of items:

const m = new Menu('Doodle2', [
  { text: 'Hello', action: () => print('Hello') },
  { text: 'Quit', action: () => task.quit() },
]);
Each item is an object (chapter 5). Its text is what the menu shows, and its action is a function that is called when you choose the item. Here the actions are arrow functions, as in chapter 4: nothing happens when the menu is made, only when an item is chosen.

The word new in front of Menu means "make a new one of these". You'll see new in front of a few other names in JavaScript, such as new Date() in chapter 9.

To show the menu, call wimp.menus.openAt when the user clicks Menu over the window. It needs the menu, the click event (so it knows where the pointer is) and the task that owns the menu:

w.on('click', (ev) => {
  if (ev.button === 'menu') {
    wimp.menus.openAt(m, ev, { task });
  }
  return true;
});
{ task } is a short way of writing { task: task }: an object with a property called task whose value is the variable task.

More about menu items

Items can have other properties besides text and action:

ticked: true
shows a tick beside the item, for an option that is on.

shaded: true
greys the item out, so it can't be chosen - for example Clear when there's nothing to clear.

dotted: true
draws a dotted line under the item, to divide the menu into groups.

submenu: ...
gives the item an arrow, and something that opens when you move the pointer over the arrow: another menu, or a dialogue box such as an Info box or a Save box.

Making the menu

The menu is made by a function, doodleMenu, which is called each time the menu is opened. Why not make it once, at the start, as in the example above? Because some of its items change: Clear should be shaded only while the drawing is empty, and the tick in the colour menu should be beside the colour in use now. Making the menu afresh each time means it always shows things as they are:

shaded: lines.length === 0 is worked out when the menu is made: true if there are no lines. And lines.length = 0, in Clear's action, empties the array. (lines is a const, so it can't be given a new, empty array, but the array it names can still be changed.)

The colour menu

RISC OS has a standard menu for choosing one of the sixteen desktop colours, and colourMenu makes it:

colourMenu('Colour', colour, (n) => { colour = n; })
It is given the menu's title, the colour to tick, and a function to call with the number of the colour chosen. The number is a Wimp colour, the same numbers as wimpColour uses in chapter 7, so Doodle2 keeps the colour as a number and turns it into a colour for drawing when a line is started: wimpColour(colour).

An icon on the icon bar

The icons on the right of the icon bar belong to applications that are running. Clicking Select on one usually opens a window, and Menu gives the application's menu - even when none of its windows is open. task.addIconbarIcon puts one there:

sprite
the name of the picture to show. Here it is file_aff, the Filer's picture for a Draw file, which suits a drawing program. Any sprite the desktop knows will do: application is a plain application icon. Chapter 13 shows how a program can have a picture of its own.

onClick
a function called when you click Select (or Adjust) on the icon. Doodle2 opens its window, in front of the others.

menu
the menu to open when you click Menu on the icon: a menu, or a function that makes one, as here. The desktop opens icon bar menus just above the icon bar, as RISC OS always does.

You can also give an icon some text to show underneath it, as the disc drives have.

Keeping going without a window

There is one important difference from Doodle: Doodle2 doesn't have the line

w.on('close', () => task.quit());
So when you close its window, the window closes but the program carries on: its icon is still on the icon bar, and clicking it opens the window again, with your drawing still in it. That is how RISC OS applications normally behave. They stop only when you choose Quit from their menu.

A program keeps running as long as it has something that could make more of it happen: a window, an icon bar icon, or a timer. A program with none of these has nothing left to do, so it finishes.

You can see Doodle2 in the Task Manager's window (click Select on the Acorn icon at the right of the icon bar) with the other tasks. Choosing Quit from Doodle2's menu calls task.quit(), which closes its windows, removes its icon and ends the task.

The Quit message

Programs can also be told to stop from outside: by the Task Manager's menu, or when you shut the desktop down. Then RISC OS sends each program a message called Quit. A program asks to hear about a message with task.onMessage:

A real RISC OS program must stop when it gets a Quit message. Here the desktop stops the program anyway, but the Quit message is the place to do any tidying up first - saving work that hasn't been saved, for example.

Summary

  • new Menu(title, items) makes a menu. Each item is an object with text and an action function, and may have ticked, shaded, dotted and submenu.

  • Open a menu when Menu is clicked with wimp.menus.openAt(menu, ev, { task }). Make the menu in a function if its items change.

  • colourMenu(title, colour, pick) is the standard colour menu; infoBox(task, {...}) makes an Info box to use as a submenu.

  • task.addIconbarIcon({ sprite, onClick, menu }) puts an icon on the icon bar.

  • A program keeps running while it has a window, an icon bar icon or a timer. task.quit() stops it.

  • task.onMessage('Quit', ...) is called when the desktop tells the program to stop.
