So far your programs have printed text and asked questions. Real RISC OS programs have windows of their own, with a title bar and a close icon, that you can move around the desktop. In this chapter you'll open your first window, put a label and a button in it, and make the button do something when it's clicked.

Tasks and the Wimp

Every program running on the desktop is a task. Click Select on the Acorn icon at the right-hand end of the icon bar, and the Task Manager window lists them all: the Filer, the Pinboard, Edit if it's loaded, and any of your programs that are running.

The part of RISC OS that looks after tasks and their windows is the Window Manager, usually called the Wimp (Windows, Icons, Menus and Pointer). The Wimp draws the window frames, moves windows about when you drag their title bars, and tells each task when something happens that it should know about: a click in one of its windows, a key being pressed, a window needing to be redrawn.

When your program runs, it is already a task: the name task stands for it. You ask the Wimp for things through task and the other names that every script has ready to use (chapter 1 used print and input, which are two of them).

Making the window

task.createWindow makes a new window belonging to your task. What it's given, between the { and }, is an object, like the ones in chapter 5: a set of named values that describe the window. The ones used here are:

title
The text in the window's title bar.

x, y
Where on the screen the window's top-left corner goes, in pixels from the top-left of the screen.

w, h
How wide and how high the window is to start with.

extent
The size of the whole work area: the "paper" inside the window. The window is a view onto part of it. Here the work area is the same size as the window, so there is nothing more to scroll to; later programs make it bigger.

createWindow gives back the new window, and the program keeps it in the constant w. A new window isn't shown until you open it, which is what w.open() does, on the last line.

Ending the program

The middle of the program is new:

w.on('close', () => {
  task.quit();
});
w.on says what to do when something happens to the window. The first thing given to it, 'close', is the name of the event: here, someone clicking the close icon. The second is a function - an arrow function, as in chapter 4 - to be called when it happens. A function that is called when an event happens is called an event handler.

This handler calls task.quit(), which ends the program: the task closes its windows and disappears from the Task Manager.

Programs that wait

There is something very different about this program. The programs in chapters 1 to 5 did their work from the top to the bottom and then finished. This one gets to the bottom almost at once - it makes a window, sets up a handler and opens the window - but it hasn't finished. It is waiting for something to happen.

Nearly all desktop programs work like this. The main part of the program sets things up; after that, everything happens in event handlers, called by the Wimp when there's something to do. This is called event-driven programming, and it is how the rest of this book works.

A program keeps running as long as it has something the Wimp could call: an open window, an icon on the icon bar, or a timer (chapter 9). So it's important to end it when it's done. Try taking the three lines of the close handler out of Window1 and running it again. The window closes when you click its close icon, but the program is still there in the Task Manager's list, with no window: nothing will ever happen to it again. Click Menu on its name in the Task Manager window and choose Task 'Window1' > Quit to get rid of it.

Choosing the tools

When you don't say otherwise, a window gets the full set of tools: back, close and toggle size icons, a title bar, scroll bars and a size icon. Often you don't want them all. The flags in the window's description say which to have:

flags: { title: true, close: true, back: true, moveable: true },
This gives a title bar, a close icon and a back icon, and lets the window be moved; there are no scroll bars and it can't be resized. The flags you'll use most are:

title      a title bar           moveable   can be dragged about
close      a close icon          toggle     a toggle size icon
back       a back icon           size       a size icon
vscroll    a vertical scroll bar hscroll    a horizontal scroll bar
You can also choose the window's colours. colours: { workBg: 0 } makes the work area white instead of the usual light grey. The number is one of the sixteen Wimp colours, which chapter 7 lists.

Where things are

Everything in a window is placed by its position in the work area, counted in pixels from the work area's top-left corner. x gets bigger to the right, and y gets bigger going down:

 (0,0) ----------------> x
   |
   |      (100,50)
   |         *
   |
   v
   y
Note: this is how positions work in the programs in this book, and in most other computer graphics. Real RISC OS measures in OS units, two to a pixel, and has y going up the screen; if you read other RISC OS programming books, remember the difference.

Icons in a window

The little boxes in RISC OS windows - labels, buttons, places to type - are all icons. You can give a window some by listing them in its description. This program has two: a label, and a button that counts how many times it has been clicked:

Describing icons

icons is an array, and each icon in it is an object. Every icon has a position and size in the work area (x, y, w and h) and usually some text. The rest describe how it looks and behaves:

hcentre
Put the text in the middle of the icon (otherwise it starts at the left).

border, filled
Draw a border round the icon, and fill in its background.

validation: 'R5,3'
Give it the three-dimensional look of a RISC OS action button. (A validation string holds extra instructions for an icon; R5 means an action button's border, and the 3 after the comma is the Wimp colour it is filled with while it is selected.)

button: 'click'
Tell the program when the icon is clicked. An icon without a button type, like the label, just sits there.

The window keeps its icons in an array called icons, in the order they were listed, so w.icons[0] is the label and w.icons[1] is the button. The program gives them names, label and button, to make the rest of it easier to read.

Responding to a click

When the button is clicked, the window gets a 'click' event:

w.on('click', (ev) => {
  if (ev.icon === button) {
    clicks = clicks + 1;
    label.setText(`Clicked ${clicks} times`);
  }
});
This time the handler has a parameter, ev. When the Wimp calls it, it passes an object that describes the event: for a click, which mouse button it was, where it was and which icon it was on. ev.icon is the icon, so the handler checks it was the button before counting the click.

label.setText(...) changes the text in the label icon, and the Wimp redraws it. Notice that the variable clicks is declared at the top of the program, outside the handler, so it keeps its value from one click to the next. If it were declared inside the handler, it would start again at 0 every time.

Here the whole handler is on one line:

w.on('close', () => task.quit());
It means exactly the same as the three-line version in Window1: an arrow function whose body is just one call doesn't need the braces.

Summary

  • Every program on the desktop is a task; the Wimp looks after tasks and their windows.

  • task.createWindow({...}) makes a window, described by title, x, y, w, h, extent, flags and colours. w.open() shows it.

  • Desktop programs are event-driven: they set things up, then event handlers do the work. w.on('close', ...) and w.on('click', ...) set handlers.

  • Call task.quit() to end a program, usually when its window is closed.

  • Positions are in pixels from the top-left of the work area, with y going down.

  • Icons are listed in the window's icons; w.icons[n] gets one, ev.icon says which was clicked, and setText changes its text.

Exercises

1 Change Window1 so that its window is 600 pixels wide, 100 high, and has only a title bar and a close icon.

2 Give Window2 a second button, Reset, that puts the count back to 0.

3 Make Window2's label say Clicked 1 time after the first click, not Clicked 1 times.

4 Change the title of Window2's window to show the count, using w.setTitle(...), which works like setText.

Answers

1 Change the size and add flags: 
  x: 200, y: 150, w: 600, h: 100,
  extent: { w: 600, h: 100 },
  flags: { title: true, close: true, moveable: true },
(Include moveable, or you won't be able to drag the window.)

2 Add a third icon, below or beside the first button (and make the window taller or wider to fit it). Give it button: 'click' like the first button, or its clicks won't be reported: 
    { x: 70, y: 112, w: 120, h: 40, text: 'Reset',
      border: true, filled: true, hcentre: true,
      button: 'click', validation: 'R5,3' },
Then check for it in the click handler: 
  } else if (ev.icon === w.icons[2]) {
    clicks = 0;
    label.setText('Not clicked yet');
  }
3 Choose the word with an if: 
    let word = 'times';
    if (clicks === 1) {
      word = 'time';
    }
    label.setText(`Clicked ${clicks} ${word}`);
4 Add this line to the click handler, after counting the click: 
    w.setTitle(`Counter: ${clicks}`);
