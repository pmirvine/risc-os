Doodle2 is about eighty lines long, and every feature you add makes it longer. Real applications are thousands of lines long, and nobody could find their way round a program that size in one file. In this chapter you will learn how JavaScript programs are split into modules - separate files that each do one job - and split Doodle into two.

Modules

A module is a file of JavaScript that shares some of what it defines with other files, and uses things shared by others. Each module does one job, and it only needs to say what it offers and what it needs; everything else inside it is its own business.

Splitting a program up like this has several advantages:

  • Each file is short enough to understand on its own.

  • You can change how a module works inside without touching the rest of the program, as long as what it offers stays the same.

  • A good module can be used again in another program.

This is how the desktop's own applications are written. Edit, for example, is about a dozen modules: one for the document, one for its windows, one for finding text, one for its dialogue boxes, and so on.

Doodle3

Doodle3 is Doodle2 split into two modules, kept together in a directory called Doodle3:

Picture
the drawing itself: the lines, and how to draw them.

Main
everything else: the window, the menu, the icon bar icon, and what happens when you click.

To run Doodle3, double-click Main. It works just as Doodle2 did:

The Picture module

This is the drawing part of Doodle2, reorganised into functions. There are two new ideas, which the next two sections explain, and two short ways of writing things you already know:

  • if (!drawing) return false; has no curly brackets. When an if controls just one statement, the brackets can be left out and it can go on one line. From here on the book uses this short form for one-line ifs; use the brackets whenever there is more than one statement.

  • { x, y } is short for { x: x, y: y }: when a property has the same name as the variable holding its value, you need only write the name once. Likewise { colour, points: [...] } has a property colour set from the parameter colour.

export

The word export in front of a function means other modules may use it. Picture exports six functions: startLine, addPoint, endLine, clear, isEmpty and drawPicture. Between them they are everything the rest of the program needs to do with the drawing.

You can export variables too, by putting export in front of const or let, but it's usually better to export functions, as Picture does, and keep the variables to yourself.

Module scope

The variables lines and drawing aren't exported, so no other module can see them. Each module has its own scope: names made at the top level of a module belong to that module, just as variables made inside a function belong to the function (chapter 4). If Main tried to use lines directly, it would get the error lines is not defined.

That is deliberate. Because the lines are private, Main can only change the drawing by calling Picture's functions, so there is only one place where a mistake with the lines can be. And Picture could be changed to keep its lines some other way without Main noticing.

Notice that drawPicture takes the graphics context g as a parameter. Picture doesn't know anything about windows: it just draws, onto whatever it is given.

The Main module

import

The first lines say what Main needs from other modules:

import { Menu, colourMenu, infoBox, wimpColour, wimp } from 'riscos';
import {
  startLine, addPoint, endLine, clear, isEmpty, drawPicture,
} from './Picture';
import { ... } from ... lists the names wanted between curly brackets, and says which module they come from.

'riscos' is the module that holds all the helpers a script has ready to use: print, input, sleep, Menu, colourMenu, infoBox, saveAs, wimpColour, wimp, vfs and the rest (appendix B lists them). In a script they are simply there; a module has to ask for the ones it uses. That makes the top of a module a handy list of everything it depends on.

'./Picture' is another file. ./ means "in the same directory as this module", so this is the file Picture beside Main. (A name like './Picture.js' would also find a file called Picture/js, which is how such files are named in RISC OS. And '../Picture' would look in the directory above.)

The name in import must match the name exported exactly. If you ask for something the module doesn't export, the program doesn't start, and the error says the module does not provide an export named the name you asked for.

The start function

A program written as a module doesn't do its work at the top level, as a script does. Instead it exports a function called start:

export default function start(task, ctx) {
  ...
}
When you double-click Main, the desktop loads Main and every module it imports, and then calls its start function, giving it the program's task and ctx (which a script also has ready to use). default marks start as the main thing the module exports: the function to call to run it.

Everything that was at the top level of Doodle2 is now inside start: the window, the menu, the click handlers and the icon bar icon. Apart from that, and using Picture's functions instead of lines, it is the same program.

A module with no start function isn't a program, so it can't be run on its own. Try double-clicking Picture: you'll be told it doesn't export a start function. Picture is only there to be used by Main.

Scripts or modules?

The desktop tells the two apart by looking at the program: if it uses import or export, it is a module. Both kinds are JSScript files, and both are run the same way. A short program is simplest as a script; as soon as a program grows big enough to split up, make it a module.

The desktop's own applications are modules, and they start in exactly the same way: Edit, Draw, Paint and the rest each export a start function that is given a task and a context, and they import what they need from the desktop's modules. Doodle3 is written the way they are.

Summary

  • A module is a file that exports some names and imports others. Split a program into modules, each with one job, once it gets long.

  • export in front of a function (or variable) lets other modules use it. Everything else at the top level of a module belongs to that module alone.

  • import { a, b } from './Name' uses names exported by the file Name in the same directory. import { print, Menu } from 'riscos' gets the desktop's helpers.

  • A module program exports default function start(task, ctx), which the desktop calls to run it. Run it by double-clicking the module with the start function.

Exercises

1 Add a function lineCount to Picture that returns the number of lines in the drawing, and use it in Main to show the count in the window's title after each new line: Doodle3 (5 lines).

2 What happens if you remove the word export from clear in Picture, and run Main? Why?

3 Move the Info box into a module of its own, called About, which exports a function aboutBox(task) that makes it. Use it in Main.

4 Make a copy of Doodle3's Picture module in a new directory, and write a short Main for it that draws a single straight line when the program starts, without any mouse or menu handling. What does this tell you about the design of Picture?

Answers

1 In Picture: 
export function lineCount() {
  return lines.length;
}
Add lineCount to Main's import from './Picture', and in the click handler, after startLine, set the title: w.setTitle(`Doodle3 (${lineCount()} lines)`);

2 The program doesn't start: Main imports clear, and Picture no longer provides it. The error names the missing export.

3 The file About: 
import { infoBox } from 'riscos';

export function aboutBox(task) {
  return infoBox(task, {
    name: 'Doodle3', purpose: 'Draws doodles',
    author: 'A. Programmer', version: '1.00',
  });
}
In Main, import { aboutBox } from './About'; and const info = aboutBox(task);, and remove infoBox from Main's import from 'riscos'.

4 A Main that only draws: 
import { startLine, addPoint, drawPicture } from './Picture';

export default function start(task, ctx) {
  startLine('blue', 20, 20);
  addPoint(200, 150);
  const w = task.createWindow({
    title: 'Line', x: 200, y: 200, w: 240, h: 180,
    extent: { w: 240, h: 180 },
    flags: { title: true, close: true, moveable: true },
    colours: { workBg: 0 },
  });
  w.useCanvas((g) => drawPicture(g));
  w.on('close', () => task.quit());
  w.open();
}
Picture didn't need changing at all: it knows nothing about mice, menus or windows, so it can be used in any program that needs a drawing.
