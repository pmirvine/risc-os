In this last chapter you will put together everything the book has covered in one complete program: the game of Snake. It has a window that is redrawn many times a second, keyboard control, sound, an icon on the icon bar with a menu, a file that remembers the best score, and it is split into modules. Finally you'll package it as a proper RISC OS application, with its own icon in the Filer.

Playing the game

Before looking at how it works, play it:

1 Open HardDisc4.$.Examples.JS and double-click !Snake. A snake icon appears on the icon bar and the game's window opens.

2 Steer the snake with the arrow keys. Each piece of red food you eat makes the snake one cell longer and scores a point.

3 If the snake runs into the edge of the board, or into itself, the game is over. Press Space to play again.

4 Click Menu on the window or on the icon bar icon for Info, New game and Quit.

The window's title shows your score and the best score so far. Close the window and the game pauses; click the icon bar icon to carry on.

Planning the program

With a program of any size it pays to think before typing. Two questions help: what does the program need to remember? and what happens, and when?

What the program remembers

The board is a grid of cells, 24 across and 18 down. A cell is identified by its column and row, which you can keep in an object such as { x: 6, y: 9 }, with x counting from 0 at the left and y from 0 at the top.

The snake is a list of cells, so it is an array of these objects. The first element is the head:

   x:  3  4  5  6  7
y: 9   .  T  #  H  .      snake = [ { x: 6, y: 9 },   the head (H)
                                    { x: 5, y: 9 },
                                    { x: 4, y: 9 } ]  the tail (T)
The direction the snake is travelling is also an object: how far one step moves it in x and in y. Right is { x: 1, y: 0 }, up is { x: 0, y: -1 } (y gets smaller going up), and so on.

Add the food (another cell), the score, and whether the game is over, and that is everything. It all goes in one object, game.

What happens at each step

The game moves in steps, a few times a second. At each step:

1 Work out the cell in front of the head, in the current direction.

2 If that cell is off the board, or part of the snake, the snake has crashed: the game is over.

3 Otherwise it becomes the new head, at the front of the array.

4 If the food is there, the score goes up and new food appears somewhere else. The tail stays where it is, so the snake is now one cell longer.

5 If not, the last cell is removed from the tail, so the snake stays the same length: it has moved.

Between steps the player may press arrow keys, which change the direction for the next step.

Dividing it up

The program has three modules, each with one job:

Game       the rules: the game object, turning and stepping.
           Knows nothing about windows, drawing or keys.
Board      drawing a game in a window's canvas.
!RunImage  the desktop program: the window, the keys, the
           clock, the menu, the icon bar and the score file.
Keeping the rules apart from the desktop makes each part simpler to read and to change. You could replace Board with a completely different look without touching the rules at all.

The rules

Here is the Game module, !Snake.Game:

It exports the size of the board, the four directions and three functions. The functions isSnake and placeFood aren't exported: they are only used inside the module, so nothing else needs to know about them.

newGame

newGame builds and returns a fresh game object, as planned. It keeps two directions: dir, the way the snake is going now, and next, the way it will go at the next step. You'll see why in a moment.

turn

turn is called when an arrow key is pressed. It mustn't let the snake turn straight back on itself, because it would immediately crash into its own neck. Going back means going in exactly the opposite direction, where both x and y are the negatives of the current ones: the opposite of { x: 1, y: 0 } is { x: -1, y: 0 }. If that's what was asked for, the function returns straight away and nothing changes.

The new direction is kept in next, and only becomes dir at the next step. If turn changed dir directly, a quick player could press Up and then Left between two steps while going right - and Left would be allowed, because the snake is then "going up", although it hasn't yet moved. Checking against dir and setting next avoids that.

step

step follows the plan exactly. It uses two array methods, one new and one you met in chapter 10's exercises:

array.unshift(item)    adds item at the start of the array
array.pop()            removes the last item from the array
Together they move the snake: a new head goes on the front and the old tail comes off the back. When the snake eats, the pop is skipped, so it grows.

step returns a string saying what happened - 'moved', 'ate' or 'crashed' - so that the desktop part of the program can make the right noise.

The test for being outside the board is long enough to split over two lines. JavaScript doesn't mind where a statement is broken, as long as the line obviously isn't finished - here it ends with ||.

placeFood

The food must go in a random cell, but not one the snake is in. The easiest way is to keep choosing random cells until one is free. That is a job for a loop you haven't met before, do ... while:

do {
  ... choose a cell ...
} while (isSnake(game, cell));
It is like a while loop with the test at the end instead of the beginning, so the body always runs at least once. That's exactly right here: there's no cell to test until one has been chosen.

Drawing the board

The Board module, !Snake.Board, draws everything:

It imports COLS and ROWS from Game, and from them works out the size of the board in pixels, which it exports for the main program to size the window with. A module can import from another module that itself imports: the chain is followed automatically.

drawBoard draws the whole board from scratch each time, in the same order you would paint it: the grass, then the food, then the snake, then any message on top. Redrawing everything is simple, and with a board this size it is easily fast enough.

Each cell is drawn two pixels smaller than the grid, starting a pixel in, which leaves a thin line of grass between the cells so you can see how long the snake is. The head is drawn a second time, in yellow, after the body.

The message uses textAlign = 'center', which makes fillText centre the text on the x position it is given, so the text sits in the middle of the board whatever its length.

The main program

!Snake.!RunImage brings everything together. It is the longest file, so here it is a piece at a time. First the imports and two constants:

KEYS is an object used as a lookup table: its property names are the Wimp key codes of the four arrow keys (see appendix B) and its values the directions they point. Property names are really strings, but a number works as a property name too. Given a key code, KEYS[code] is the direction - or undefined for any other key.

The square brackets are new with objects. game.score looks up the property called score; KEYS[code] looks up the property whose name is held in the variable code, whatever that is at the time. It is how you use an object when you don't know which property you want until the program runs - just as list[i] picks an array element by a number held in i.

Starting up

start is an async function, because it uses await to read the best score from its file before anything else happens (the function loadBest is at the end of the file). game is declared with let because a new game replaces it with a new object.

The window is exactly the size of the board. Notice the drawing function: (g) => drawBoard(g, game). Each time the window is redrawn it uses whatever game holds at that moment, so after game = newGame() the next redraw shows the new game without any more work.

Clicks and keys

A Menu click opens the program's menu. Any click gives the window the input focus with wimp.setCaret(w), so that key presses come to it: its title bar turns cream to show it has the focus.

The key handler looks the key code up in KEYS. if (dir) uses the rule from chapter 8: a direction is a non-empty string, which counts as true, and undefined counts as false. If it finds a direction, it turns the snake. If the game is over, Space starts a new one. For any other key the handler returns nothing, which tells the Wimp the key wasn't used, so it can go on to other programs that want it (chapter 8). (F12 and the other keys the desktop keeps for itself never reach the program at all.)

The clock

The game moves every 150 milliseconds. w.isOpen is true while the window is open on the screen and false once it has been closed. So when the window has been closed, or the game is over, the timer function returns at once and nothing moves: the game is paused. Otherwise it takes one step, plays a note if the snake ate or calls crashed if it crashed, updates the title and asks for the window to be redrawn.

sound(1, -15, 180, 1) plays a short note: channel 1, loudness -15 (the loudest), pitch 180 and length 1 (a twentieth of a second) - the same numbers BBC BASIC's SOUND statement takes. beep() sounds the computer's usual warning beep.

Functions inside start

These functions are declared inside start, so they can use its variables - game, best, w and the rest - just as the event handlers can. A function declaration can be used anywhere in the function that contains it, even above where it is written, which is why the timer can call crashed although it comes later.

crashed saves a new best score to the score file. newGameNow replaces the game and makes sure the window is open and has the focus.

The menu and the icon bar

The Info box is made once, when the program starts, and used as the Info item's submenu, as in chapter 10. makeMenu builds the menu; it is used both by the window and by the icon bar icon, so Menu gives the same menu on either.

The icon bar icon uses the sprite !snake, which is the program's own - you'll see where it comes from in the next section. Clicking the icon opens the window again if it has been closed.

As with Doodle2 in chapter 10, closing Snake's window doesn't end the program: the icon stays on the icon bar, and Quit on the menu ends it. That's how most RISC OS applications behave. The last line of setting up answers the Quit message, so that the Task Manager can quit Snake too - when you shut the computer down, for example.

Keeping the best score

The best score is kept in a Text file called HighScore. It goes in the same directory as the program: ctx.dir is the directory the program was run from, so ctx.dir + '.HighScore' is its full name, wherever the game has been copied to.

The file just holds the number as text, so it is written with String(best) and read back with Number(...). If the file doesn't exist yet - the first time the game is played - or doesn't hold a number, loadBest gives 0. Number('rubbish') is NaN ("not a number"), and NaN || 0 is 0, because || gives its right-hand side when the left-hand side counts as false.

Note: real RISC OS applications keep settings like this in Choices:, the directory !Boot.Choices, so that the application itself can be on a read-only disc or shared over a network. Keeping it inside the application is simpler, and fine for a game of your own.

Making it an application

You have been running JavaScript programs by double-clicking a single JSScript file. Snake is different: it is an application. In RISC OS an application is a directory whose name starts with !. The Filer shows it with the application's own icon rather than as a directory, and double-clicking it runs the application instead of opening the directory:

To see inside, hold down Shift and double-click it:

Each of the files starting with ! has a special job:

!Run       What happens when you double-click the application.
!Boot      What happens when the Filer first sees it.
!Sprites   The application's icons.
!Help      Text shown by Help on the Filer's menu.
!RunImage  The program itself: here, a JavaScript module.
Board and Game are the program's other modules, and HighScore appears once a game has been played.

!Run

!Run is an Obey file: a list of * commands, run one after another, as if you had typed them at the command line (F12).

The first line, starting with |, is a comment. The rest does three things:

1 Set Snake$Dir <Obey$Dir> sets a system variable. While an Obey file runs, Obey$Dir holds the name of the directory it is in, so Snake$Dir ends up holding the application's full name, for example ADFS::HardDisc4.$.Examples.JS.!Snake. Anything can then find the application's files through <Snake$Dir>, wherever it has been put.

2 IconSprites loads the application's sprites into the Wimp's sprite pool, where windows and the icon bar can find them by name. That's how addIconbarIcon finds !snake.

3 Run <Snake$Dir>.!RunImage %*0 runs the program. %*0 passes on anything that followed the application's name when it was run - for example a file dropped on it. Because !RunImage is a JSScript file, Run starts it with JSRun, and the task is named after the application, Snake. The program's ctx.dir is the application directory.

!Boot and !Sprites

The Filer runs an application's !Boot file the first time it displays the application, even before it has been run. Snake's loads the sprites, so that the Filer can show the snake icon straight away.

The Filer shows an application with the sprite that has the application's name in lower case, !snake, and uses sm!snake for its small-icon display. Both are in the sprite file !Sprites. You can look at them, and change them, in Paint: double-click !Sprites in the application directory.

!Help

!Help is an ordinary Text file. Click Menu over the application in a directory display and choose App. '!Snake' > Help to read it.

Your own copy

Because everything is found through ctx.dir and <Snake$Dir>, the application works from anywhere. Drag !Snake into your MyProgs directory to make your own copy, and change that one: the original stays in Examples.JS to go back to.

Making an application of your own

To turn any program of yours into an application:

1 Make a directory whose name starts with !, for example !Doodle. (To open it, Shift-double-click it.)

2 Put the program in it, as a JSScript file called !RunImage. It can be a script or, as here, a module with other modules beside it.

3 Make a !Run file: in Edit, Menu > Create > Obey. Copy Snake's, changing Snake$Dir to your application's name.

4 If you'd like your own icons, copy Snake's !Sprites and !Boot and change the sprites in Paint, renaming them after your application. Otherwise leave out the IconSprites line and use one of the Wimp's sprites for your icon bar icon, such as 'application'.

Where to go from here

You have come a long way from print('Hello, world!'): values and variables, decisions and loops, functions, arrays and objects; windows, drawing, the mouse and keyboard, timers, menus, the icon bar, modules and files. That is the whole toolkit of most desktop programs.

The best way to carry on is to write programs of your own. Start small, get something working, and add to it a piece at a time, running it at every stage - that's how Snake was built. Some ideas:

  • A calculator, a clock with an alarm, or a timer for boiling eggs.

  • A game: noughts and crosses, a memory game with cards to turn over, or Breakout.

  • A drawing program with a choice of shapes, building on Doodle.

  • A program that reads a Text file and draws a bar chart of the numbers in it.

When you want to know more about JavaScript itself, appendix A lists what the book didn't cover, and MDN Web Docs (from Mozilla) is a complete reference to the language on the web. Appendix B lists the parts of this desktop's programming interface the book has used.

Summary

  • Plan a program by deciding what it must remember and what happens when.

  • Split a larger program into modules with one job each; keep the rules apart from the display.

  • unshift adds to the start of an array and pop removes from the end. A do ... while loop always runs at least once.

  • An object can be a lookup table, from key codes to directions for example.

  • A timer made with task.every drives a game; sound and beep make noises.

  • An application is a directory whose name starts with !, with !Run, !Boot, !Sprites, !Help and the program itself, usually called !RunImage.

  • <Obey$Dir> (in !Run), a variable such as <Snake$Dir> and ctx.dir (in the program) let an application find its own files wherever it is.

Exercises

Make your own copy of !Snake first (see Your own copy above), and change that.

1 Make the board bigger, or the cells smaller. Which module do you need to change?

2 Add a key, P, that pauses and restarts the game.

3 Make the game speed up as the score goes up.

4 Change the rules so that the snake goes off one side of the board and comes back on the other, instead of crashing into the edge.

5 Draw the score in the corner of the board instead of (or as well as) in the title bar.

Answers

1 Change COLS and ROWS in Game, or CELL in Board. Everything else - the size of the window included - is worked out from them. (Check that the starting snake is still on the board.)

2 Keep a variable, let paused = false;, in start. In the key handler add 
if (ev.char === 'p' || ev.char === 'P') {
  paused = !paused;
  return true;
}
and in the timer function return early if paused is true.

3 task.every always uses the same interval, so use task.after instead, which runs a function once, after a delay. Put the step in a function that sets up the next step itself, with a delay that depends on the score: 
function tick() {
  task.after(Math.max(60, SPEED - game.score * 5), tick);
  ... the body of the old timer function ...
}
tick();
The next step is set up first, at the top of tick, so that the early return when the game is paused or over doesn't stop the clock for good.

4 In step, instead of testing outside, wrap the new cell's position round: 
cell.x = (cell.x + COLS) % COLS;
cell.y = (cell.y + ROWS) % ROWS;
Adding COLS first keeps the value positive when cell.x is -1.

5 drawBoard is already given the whole game, so the score is there, in game.score. Add this at the end of drawBoard, before the message: 
g.fillStyle = 'white';
g.textAlign = 'left';
g.font = '14px sans-serif';
g.fillText(`Score ${game.score}`, 6, 18);
