In this chapter your programs start to respond to you. You'll write Doodle, a small drawing program that you draw in with the mouse, and Keys, which moves a ball around its window with the arrow keys.

Clicks in a window

In chapter 6, the Wimp told Window2 when its button was clicked, because the button icon asked for clicks with button: 'click'. A click in the rest of the window - the work area - isn't reported unless the window asks for it too. It does that with workButton in its description:

workButton: 'click',
Now every press of a mouse button in the work area gives the window a 'click' event. The event object says where and which button:

ev.x, ev.y
Where the pointer was, in the work area: pixels from the top-left, with y going down.

ev.button
'select', 'menu' or 'adjust'.

Here is a handler that prints where you clicked, which you could try in a window of your own:

w.on('click', (ev) => {
  print(`${ev.button} at ${ev.x}, ${ev.y}`);
  return true;
});
The return true at the end tells the Wimp that the program has dealt with the click. That matters most for the Menu button: if a click handler doesn't return true, the Wimp goes on to do its usual thing with the click - for Menu, opening a menu the window has been given. Returning true says "leave it to me".

Remembering what was drawn

Chapter 7 explained that the Wimp may ask for a window to be drawn again at any time. So a drawing program can't just draw a line when you move the mouse and forget about it: it has to remember everything that has been drawn, so its redraw function can draw it all again.

Doodle keeps an array, lines, with an object for every line you've drawn. Each object has the line's colour and an array of the points it goes through:

{ colour: 'red', points: [{ x: 40, y: 120 }, { x: 50, y: 118 }, ...] }
The mouse handlers only add points to the array and call w.invalidate(). The redraw function draws whatever is in the array. That way the picture always matches what the program remembers, whether it's being drawn because you moved the mouse or because a window was dragged across it.

Doodle

Hold down Select and move the mouse to draw. Click Adjust to change to the next colour: the title bar says which colour you're using.

Starting a line

When Select is pressed, the click handler makes a new line object, puts the point where you clicked in it, and adds it to lines. It also keeps it in the variable drawing, meaning "the line being drawn now".

When Adjust is pressed, the handler moves on to the next colour. % (remainder) makes the number go back to 0 after the last colour, so the colours go round and round:

colour = (colour + 1) % colours.length;

Following the mouse

The rest of the line is drawn as the mouse moves. A window that listens for 'pointermove' is told every time the pointer moves over it. The event has ev.x and ev.y, and also ev.buttons, which says which buttons are being held down: 1 means Select (and 0 means none).

w.on('pointermove', (ev) => {
  if (drawing && ev.buttons === 1) {
    drawing.points.push({ x: ev.x, y: ev.y });
    w.invalidate();
  } else {
    drawing = null;
  }
});
While Select is held down, each move adds a point to the line being drawn. As soon as the pointer moves with Select not held down, the line is finished, and drawing is set back to null, a value that means "nothing". Next time Select is pressed, a new line starts.

Values that count as true or false

Look at the test if (drawing && ev.buttons === 1). drawing isn't a comparison: it is either an object (the line being drawn) or null. That is allowed. Where JavaScript expects true or false and gets some other value, it treats a few values as false: false itself, 0, the empty string '', null, undefined and NaN. Everything else - any other number, any other string, any object or array - counts as true. So if (drawing) means "if there is a line being drawn", and if (!drawing) means "if there isn't". You'll see this short way of writing tests from now on.

Drawing the lines

The redraw function goes through lines with for...of, and draws each line as a path: move to the first point, then a lineTo to every point. Setting lineCap and lineJoin to 'round' gives the lines round ends and smooth corners, so they look like a felt pen instead of a ruler. A line with only one point is drawn as a dot.

Notice that the redraw function draws the whole picture every time, even when only one point has been added. That sounds wasteful, but the computer is fast enough for it not to matter, and it keeps the program simple.

The keyboard

Keys you type go to the window that has the input focus. You can see which one that is: its title bar is cream instead of grey. When you click in a JsEdit window, JsEdit gives that window the input focus, so what you type goes into it.

A program gives one of its windows the input focus with:

wimp.setCaret(w);
(The caret is the flashing text cursor; this version of the call gives the window the input focus without showing one.) After that, each key pressed gives the window a 'key' event. The event has two ways of saying which key:

ev.char
The character, as a string, for keys that type one: 'a', 'A', '7', ' '.

ev.code
A number for every key, including ones that don't type anything. For characters it's the character's code (65 for A). Some others are: 
Return   13        left arrow   &18C  (0x18C)
Escape   27        right arrow  &18D  (0x18D)
Delete  127        down arrow   &18E  (0x18E)
F1 to F9 &181 to &189   up arrow  &18F  (0x18F)
The arrow keys' codes are usually written in hexadecimal (base 16), which RISC OS writes with an & in front and JavaScript with 0x in front: 0x18C is the same number as 396. It's easier to look up key codes in hexadecimal, and the programs use it too.

Keys

The ball starts in the middle of the window. Each press of an arrow key moves it ten pixels.

The 'key' handler checks ev.code against the four arrow keys and changes x or y, and returns true to say it used the key. If the key isn't an arrow, it returns without a value (a plain return;). That tells the Wimp the program didn't want the key, and the Wimp passes it on, in case another program is waiting for it (a hot key). Only return true for keys you really use.

Math.min and Math.max keep the ball inside the window. Math.min(400 - size, x) is whichever is smaller, x or the furthest right the ball may go, so x can't get too big; Math.max(size, ...) stops it getting too small in the same way.

The window takes the input focus as soon as it opens, on the last line. But if you click in another window, that window takes the focus and the arrow keys go there instead. So Keys also asks for clicks, and takes the focus back whenever its window is clicked.

Summary

  • workButton: 'click' makes a window report clicks in its work area. The click event has ev.x, ev.y and ev.button. Return true from the handler when you've dealt with it.

  • 'pointermove' events say where the pointer is as it moves over a window; ev.buttons is 1 while Select is held down.

  • Keep everything the window shows in variables and arrays; handlers change them and call w.invalidate(), and the redraw function draws from them.

  • wimp.setCaret(w) gives a window the input focus. 'key' events have ev.char and ev.code; return true for keys you use, and nothing for others so the Wimp passes them on.

  • null is a value meaning "nothing"; 0x starts a number in hexadecimal.

  • In a test, false, 0, '', null, undefined and NaN count as false and every other value counts as true.
