In this chapter you will write your first JavaScript program, save it and run it. You will also see what happens when a program goes wrong, and write a program that asks you a question.

What a program is

A program is a list of instructions for the computer to carry out, one after another. The instructions are written in a programming language - here, JavaScript - and kept in a file. When you run the program, the computer reads the file and does what it says.

In RISC OS, every file has a file type that says what sort of file it is: Text, Sprite, BASIC and so on. A JavaScript program is a file of type JSScript. The Filer shows it with this icon, and when you double-click it, RISC OS runs it:

What is going on

The program has two lines.

The first line is a comment. Anything after // on a line is ignored by the computer: it is there for people reading the program. It is a good habit to start every program with a comment saying what it is.

The second line is an instruction, or statement:

print('Hello, world!');
print is the name of a function: a piece of code, already written for you, that does a job. To use a function you call it, by writing its name followed by brackets. Anything inside the brackets is given to the function to work with. print shows what you give it in the program's window, on a line of its own.

'Hello, world!' is a string: a piece of text. Strings are written between quote marks, so that JavaScript can tell text apart from the rest of the program. You can use single quotes (') or double quotes ("), as long as both ends match. This book uses single quotes.

The semicolon (;) marks the end of the statement, as a full stop marks the end of a sentence. JavaScript is forgiving and will usually manage without one at the end of a line, but it's clearer to put it in.

When the program has nothing more to do, it has finished: the window's title says (finished). Close the window with its close icon.

Changing the program

Programs are rarely right first time, so you'll soon be used to this cycle: change the program, save it, run it again. Edit is still showing Hello, so try it now:

1 Add a second line to the program: 
print('Hello, world!');
print('This is my second line.');
2 Press F3 and then Return (or click OK). The Save box already knows where the file lives, so there's no need to drag it again.

3 Double-click Hello in MyProgs again.

Each print gives a new line. The statements are carried out in order, from the top of the file to the bottom.

Note: if you'd like to run a program without leaving the keyboard, press Ctrl-F12 to open a task window and type the JSRun command with the program's full name, for example *JSRun HardDisc4.$.MyProgs.Hello. The program prints in the task window instead.

When things go wrong

Sooner or later, everyone types something wrong. Change print to prnt (a typing mistake anyone could make), save the file and run it. This time you get an error box:

The message tells you three things. The title bar says which program had the problem. prnt is not defined says what went wrong: JavaScript doesn't know anything called prnt. And line 2 says where. To find a line in Edit, press F5 (or choose Menu > Edit > Goto): the Goto box shows which line the caret is on, and takes you to any line number you type.

Error messages can look unfriendly, but they are trying to help. Read them carefully: nine times out of ten they tell you exactly what to fix. Appendix C lists the most common ones and what they usually mean.

Some mistakes stop JavaScript from understanding the program at all - a missing quote or bracket, for example. Then none of the program runs, and the message says so, with the line where JavaScript gave up. Try deleting the closing quote from the first print line to see this:

Invalid or unexpected token (line 2)
Put the quote back (and correct prnt) before carrying on.

There are several new things here.

input('> ') shows the text you give it - a prompt - and then waits for you to type a line and press Return. What you typed comes back as a string.

The word await in front of it means "wait for this to finish before going on". Typing takes time, and without await the program wouldn't wait for you. You'll meet await again later; for now, always put it in front of input.

const name = ... keeps the answer so the program can use it later. name is a variable: a name for a value. Chapter 2 is all about variables.

In 'Pleased to meet you, ' + name + '.' the + joins strings together. And name.length is the number of characters in the string name.

Summary

  • A JavaScript program is a file of type JSScript. Double-click it to run it.

  • Create one with Menu > Create on the Edit icon: type JSScript in the box. Save with F3.

  • A program is carried out a statement at a time, from top to bottom. End each statement with a semicolon.

  • // starts a comment, which the computer ignores.

  • print(...) shows text in the program's window. await input(prompt) asks for a line of text.

  • Strings are written between quotes, and joined with +.

  • When something goes wrong, an error box tells you what and on which line.
